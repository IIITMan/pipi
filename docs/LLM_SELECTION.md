## 2. 先纠一个直觉：闲聊不贵，延迟才贵

很多人选模型的默认逻辑是"省钱 → 选小模型"。**对皮皮这个场景，这个逻辑是错的。**

皮皮的闲聊有很强的特征：**人设 Prompt 很长**（人格 + 记忆召回 + 视觉观测）、
**用户输入很短**（一句话）、**回复也短**。算下来：

| 单轮 token 构成 | 量 |
|---|---|
| system（人格 + 记忆 + 视觉观测） | 1200 |
| 历史（近 n 轮） | 800 |
| 用户输入 | 20 |
| **输入合计** | **2020** |
| 输出 | 60 |

按 2026 年 10 月各家刊例价实算（无缓存）：

| 模型 | 单轮成本 | **一千轮** | ¥100 能聊 |
|---|---|---|---|
| **Qwen3-Flash** | ¥0.00006 | **¥0.15** | **66 万轮** |
| DeepSeek-V4-Flash | ¥0.0021 | ¥2.14 | 4.7 万轮 |
| DeepSeek-V4-Flash（缓存命中） | ¥0.0002 | ¥0.16 | 62 万轮 |
| Doubao-Seed-2.1-pro | ¥0.0139 | ¥13.92 | 7200 轮 |
| Qwen3-Plus | ¥0.0064 | ¥6.40 | 1.5 万轮 |
| Qwen3-Max（旗舰） | ¥0.0264 | ¥26.40 | 3800 轮 |
| Kimi K3（最贵） | ¥0.0464 | ¥46.40 | 2200 轮 |

> **注意第一行和最后一行差了 300 倍**，但即使最贵的 Kimi K3，
> 一千轮也只要 ¥46 —— 而一千轮大约相当于**两年半的日常闲聊**。
>
> 结论：**对话成本在皮皮的预算里可以忽略。**
> 真正的约束是**首 token 延迟**（陪伴场景超过 1.5 秒就"不像在聊天"了）
> 和**人格稳定性**（聊 20 轮后还是不是原来那个角色）。

### 省钱真正的杠杆（不是换小模型）

| 手段 | 效果 |
|---|---|
| **前缀缓存** | DeepSeek 缓存命中 ¥0.02/百万（原价 1/100）；豆包缓存 ¥1.2（原价 1/5） |
| **人格 Prompt 前置** | 把不变的 system 放 messages 最前且不改动，时间戳等变化字段塞进 user |
| **任务拆分** | 记忆抽取 / 情感分析走 `cheap_model`，不占主模型 |

**做法**（`configs/default.yaml` 已按此配置）：

```yaml
# 人格 Prompt 是每轮不变的前缀，放 messages 最前面且不改动，
# 可命中厂商前缀缓存，输入成本可降 70%+
```

> **千万别这样做**：把 `当前时间：2026-10-06 13:03` 拼进 system Prompt 开头 →
> 每轮前缀都不同 → 缓存永远不命中 → 输入成本从 ¥0.02 涨回 ¥1.00，**50 倍**。

## 2.5 平台怎么选：比模型选择更重要

前面算的都是**对话**的钱。但皮皮是一个**语音产品**，真正花钱的地方在
ASR（听）和 TTS（说）。把全链路摆在一起看：

按每天 20 轮、每轮主人说 5 秒 / 皮皮回 10 秒估算：

| 环节 | 用量 | 一年成本 | 占比 |
|---|---|---|---|
| **LLM 对话**（Qwen3-Flash） | 7300 轮 | **¥0.44** | **0.8%** |
| ASR 流式识别 | 600 分钟 | ¥10.00 | 18% |
| **TTS 语音合成** | 21.6 万字 | **¥45.36** | **81%** |
| **合计** | — | **≈ ¥56** | 100% |

> **这是整份文档最重要的一张表。**
> 你在模型选择上纠结半天省的几毛钱，在 TTS 面前毫无意义 ——
> **LLM 只占 0.8%，TTS 占 81%。**
>
> 所以选平台的第一优先级不是"哪家 LLM 便宜"，
> 而是**"哪家的 ASR + TTS 好用、稳定、便宜"**。

### 三类平台的真实差异

| 类型 | 代表 | 特点 | 适合皮皮吗 |
|---|---|---|---|
| **云厂商自营** | **火山引擎（豆包）**、阿里云百炼 | 模型 + ASR + TTS + RTC **全家桶在一家**；企业级 SLA | ✅ **强烈推荐** |
| 模型厂商直营 | DeepSeek、智谱、MiniMax | 便宜、模型强，但**不做语音** | ⚠️ 只适合做 LLM 灾备 |
| 聚合平台 | 硅基流动、OpenRouter | 一个 Key 打通多家，**但语音得另找** | ⚠️ 适合 A/B 测试期 |

**火山引擎是唯一"语音+对话+实时通话"全在一家**的平台：

| 能力 | 火山引擎（豆包） | 阿里云百炼 |
|---|---|---|
| 对话 LLM | Doubao-Seed-2.1-pro（拟人度第一） | Qwen3 系列（生态最全） |
| ASR | 豆包语音识别 2.0：流式 ¥1/小时 | 有（qwen-audio） |
| TTS | 豆包 TTS，**情感语气标签**、15 轮内声音复刻 | 有（CosyVoice） |
| 实时对话 | **端到端实时语音大模型**（ASR+LLM+TTS 一体） | 需自己拼 |
| 免费额度 | **每天 200~500 万 token 自动刷新** | 7000 万 token / 90 天 |

### 三条实用判断

**① 语音选火山引擎，对话选百炼（混合，但一个账号体系下最省事）**

- **TTS 是陪伴产品的命脉**：皮皮说"哼，你终于回来啦"和说"您好，欢迎回家"
  是两种产品。豆包 TTS 支持**情感语气标签**（可在文案里写 `[急切而发颤]`），
  还能用 5~10 秒录音**复刻专属声线**（¥150/年/音色）。
- **但百炼的 Qwen3-Flash 延迟更低（~300ms）、免费额度更实在、生态更全**。
- **可行组合**：LLM 走百炼，ASR/TTS 走火山。两套 Key，但代码里只是两个 provider。

**② 如果怕麻烦，全押火山引擎也完全够用**

豆包在**中文拟人度上本来就是第一**（见 §5），LLM 用它不亏；
而且一家搞定语音+对话，省掉跨平台联调、跨账号对账。
代价是 LLM 贵约 90 倍（¥13.92/千轮 vs ¥0.15）——
但展开到全链路，一年也就多花 **¥100 左右**。**对陪伴产品这是值得花的钱。**

**③ 一定要接两家，但不能是同一家的两个模型**

| 反模式 | 后果 |
|---|---|
| ❌ 百炼的 qwen3-flash + 百炼的 qwen3-plus | 百炼挂了两个一起挂，**零容灾** |
| ✅ 百炼 qwen3-flash + DeepSeek 官方 | 物理隔离，真灾备 |

**这一点在 `configs/degradation.yaml` 里已经落地**：
`chain: ["qwen", "deepseek", "mock"]` —— 刻意跨厂商。

### 避坑

| 坑 | 说明 |
|---|---|
| 只看 LLM 单价选平台 | TTS 占比 81%，看错了重点 |
| 用聚合平台做主力 | 多一跳延迟，且语音能力通常缺失 |
| 单一平台单点依赖 | 参考 `qwen✗ → deepseek✗ → mock` 的跨厂商链 |
| 忽略实名与备案 | 国内云平台调用 API 均需**实名认证**，未认证一律拒绝 |
| 忽略限流 | 百炼按**主账号维度合并计算**所有 Key 的调用量；突发请求会触发保护性限流。皮皮是单用户低频场景，不会碰到，但要知道 |
| 忘记在控制台手动开通模型 | 火山引擎需要手动开通模型，否则**有 Key 也调不通** |

## 4. 从小到大：云端档位全表

从最便宜/最快到最强，排成七档。**价格单位：元 / 百万 token（2026 年 10 月核价）**。

### 档位 ① 超轻量级 —— 皮皮首选 ★

| 项目 | 值 |
|---|---|
| 代表 | **Qwen3-Flash**（阿里百炼） |
| 价格 | ≤32K 输入 **¥0.2** / 输出 **¥0.8**；32K~1M 涨至 ¥1.2 / ¥4.8 |
| 上下文 | 1M |
| 首 token | ~300ms（官方称单轮推理 <100ms） |
| 擅长的 | 日常闲聊、情绪回应、短句陪伴、工具调用 |
| 一千轮成本 | **¥0.15** |

**点评**：这就是皮皮该用的档。理由不是"便宜"（便宜只是副作用），而是
**延迟最低、中文口语最自然、支持工具调用与多模态**。
Flash 档这类模型经过这两年迭代，日常闲聊的质量和旗舰的差距已经很小，
差的是复杂推理——而皮皮不需要复杂推理，需要**接得住话**。

### 档位 ② 性价比级

| 项目 | 值 |
|---|---|
| 代表 | **DeepSeek-V4-Flash** |
| 价格 | 输入 ¥1 / 输出 ¥2；**缓存命中 ¥0.02**（全网最低） |
| 上下文 | 1M |
| 首 token | ~600ms |
| 一千轮成本 | ¥2.14（开缓存 ¥0.16） |

**点评**：**降级链第二顺位**。放在这里的价值有两个：
① 与阿里物理隔离的不同厂商，单一厂商故障时互为灾备；
② 若皮皮将来打开前缀缓存，它的缓存价是全网最狠的（原价 1/100）。

> 注意它的文风**极度理性克制**，做闲聊偏"说明书味"，
> 不像 Flash 那样柔和。所以做灾备可以，做主力差一点。

### 档位 ③ 拟人性最强档

| 项目 | 值 |
|---|---|
| 代表 | **Doubao-Seed-2.1-pro**（字节火山引擎） |
| 价格 | 输入 ¥6 / 输出 ¥30；缓存命中 ¥1.2 |
| 上下文 | 1M（0915 版起从 256K 扩容） |
| 首 token | ~380ms |
| 一千轮成本 | ¥13.92 |

**点评**：**"人话感"冠军**。多方实测口径一致指向同一个结论——
豆包是国产模型里**唯一不带"机械死脑筋味"**的选手，自带网感、语气起伏、
情绪频率。做情绪陪伴文案时它的共情力是明确高一档的。

如果实测发现 Qwen3-Flash 的皮皮"太像一个礼貌的客服"，
**第一个该换的就是它**。代价是贵约 90 倍——但绝对值仍然只有
¥13.92/千轮（≈ 2.5 年的日常闲聊），对陪伴产品这是**值得花的钱**。

> **它的短板**：长逻辑和严谨推演不行，容易"一本正经地胡说八道"。
> 但皮皮不写报告，只聊天，这个短板**恰好用不上**。

### 档位 ④ 主力均衡级

| 项目 | 值 |
|---|---|
| 代表 | **Qwen3-Plus** |
| 价格 | 输入 ¥0.8 / 输出 ¥2（非思考）~ ¥8（思考） |
| 上下文 | 128K~1M |
| 首 token | ~400ms |
| 一千轮成本 | ¥6.40 |

**点评**：比 Flash 强一档，但价格贵 40 倍。**不建议做主力**，
因为延迟和语感都没明显优势。可考虑做**话题路由**：
聊到"主人今天被裁员了"这种需要真正共情的话题时，
临时切到 Plus 或 Doubao。

### 档位 ⑤ 长文特化级

| 项目 | 值 |
|---|---|
| 代表 | **Kimi K2.8 / K3**（月之暗面） |
| 价格 | 输入 ¥6.5 / 输出 ¥27；K3 更贵 |
| 上下文 | 1M+ |
| 一千轮成本 | ~¥30 |

**点评**：**皮皮用不上**。它的核心竞争力是超长文本无损精读与精准溯源，
那是研报、合同、论文场景。皮皮的单轮上下文就 2000 token。
它做角色扮演的评测也不占优（"长文专家"而非"闲聊高手"），
且推理链长导致**响应慢**——对陪伴产品是硬伤。

### 档位 ⑥ 旗舰级

| 项目 | 值 |
|---|---|
| 代表 | **Qwen3-Max** |
| 价格 | 阶梯：≤32K ¥2.5/¥10；128K~252K ¥7/¥28 |
| 首 token | ~500ms |
| 一千轮成本 | ¥26.40 |

**点评**：**留着做"少量复杂场景"的备用**，比如主人要认真讨论一个技术问题。
不要做闲聊主力——贵 176 倍却没换来陪伴场景的可见提升。

### 档位 ⑦ 海外旗舰（明确不推荐）

| 代表 | 输入 / 输出 | 相当于 |
|---|---|---|
| Claude Sonnet 4.5 | $3 / $15（≈¥21 / ¥106） | 贵 100 倍 |
| GPT-5.2 | $1.75 / $14 | 贵 80 倍 |
| Gemini 2.5 Flash | $0.15 / $0.60 | 贵 5 倍，但国内访问难 |

**为什么不做主力**（虽然它们在公开榜单上排名更高）：

1. **贵 40~80 倍**，而钱在陪伴场景不是主要矛盾，延迟和可用性才是。
2. **国内访问不稳定**：需要额外代理链路，对"主人回家 2 秒内要开口"的场景是灾难。
3. **拒答多**：海外模型的 armor（内容过滤）在情感陪伴语境下容易误伤——
   聊到"我今天好累啊，不想活了"这种情绪表达时，**它可能直接给一段热线电话**，
   而皮皮该做的是温柔地接住。**这是产品级事故**。

> **它们的正确用法**：**用它离线打磨 Prompt，不用它上线。**
> 拿 Claude 帮你把人格 Prompt 写得更好、把 20 轮对话脚本审一遍，
> 然后交给 Qwen3-Flash 或豆包去跑。这是性价比最高的用法。

## 5. 逐档点评（含国内主流 7 家实测口径）

各家社区实测的**一句话画像**（同一个问题问不同家，差的是"性格"不是"智商"）：

| 厂商/模型 | 一句话画像 | 适合皮皮吗 |
|---|---|---|
| **豆包** | 热情卷王：秒回、话多、情绪价值拉满，"唯一没有机械感" | ✅ **拟人度第一，首选换口味对象** |
| **千问 Qwen** | 全能管家：均衡、稳、生态接入最广 | ✅ **主力（Flash 档）** |
| **DeepSeek** | 冷面操盘手：精准不废话，文风克制 | ⚠️ 只做灾备，闲聊偏硬 |
| **Kimi** | 长文专家：回复语气最像真人，但慢 | ❌ 皮皮不需要长文 |
| **智谱 GLM** | 技术派：编程推理强，日常对话不如豆包自然 | ⚠️ 不用 |
| **MiniMax** | Agent 型：长程任务、多智能体 | ❌ 不对口 |
| **文心一言** | 老牌百科：中文知识丰富，风格正式 | ❌ 太正式 |

> **一个反直觉的观察**：当基础能力趋同后，**"对脾气"成了新的竞争维度**。
> 2023 年选 AI 看智商，2025 年看成本，2026 年开始看性格。
> 对陪伴产品，这恰好是**唯一重要的事**。

## 6. ⭐ 皮皮推荐配置（可直接抄）

### 三档分工

```yaml
llm:
  provider: "qwen"             # 全云端方案
  base_url: "https://dashscope.aliyuncs.com/compatible-mode/v1"
  api_key: ""                  # 用环境变量 PIPI_LLM__API_KEY

  # ① 主对话：闲聊 / 共情 / 有性格的回应
  model: "qwen3-flash"         # ≤32K 输入 ¥0.2 / 输出 ¥0.8

  # ② 辅助任务：记忆抽取 / 情感分析 / 观测摘要
  cheap_model: "qwen3-flash"   # 同款即可，已足够便宜

  timeout_s: 30
  max_retries: 2

  # ③ 降级链：qwen(主) → deepseek(备) → mock(规则回复)
  #    纯云端方案，不引入本地模型

  routing:
    enabled: true
    simple_max_chars: 8        # 短寒暄走便宜模型

  temperature: 0.8             # 陪伴场景实测最佳
```

### 成本实测

| 场景 | 计算 | 成本 |
|---|---|---|
| 一天 20 轮闲聊 | 20 × ¥0.00006 | **¥0.0012** |
| 一个月 | × 30 | **¥0.036** |
| **一年** | × 12 | **≈ ¥0.43** |

> 换成拟人最强的豆包：一年约 **¥101**。仍然是一顿火锅的钱。
> **所以真正的决策依据不是价格，是"哪个模型的皮皮更像皮皮"。**

### 降级链（两家云厂商互为灾备）

```
qwen（阿里百炼，主）
   ↓ 失败/超时/限流
deepseek（深度求索，备）        ← 物理隔离的另一厂商
   ↓ 也失败
mock（本地规则回复）           ← 不联网，永远可用
```

> **为什么是两家不同厂商而不是同一家两个模型**：
> 单厂商故障、限流、欠费时，同厂商的"备用模型"通常一起挂。
> 跨厂商才有真正的容灾意义。

### 明确不做的事

| 不做 | 原因 |
|---|---|
| ❌ 本地部署 LLM（Ollama / 3B） | 算力全给视觉与 ROS2；本地跑会抢 CPU；云端成本已可忽略 |
| ❌ 本地微调 | 需要独显；且云端模型迭代快，微调很快过期 |
| ❌ 多厂商同时在线 | 增加接入与运维复杂度，收益仅为"多一层灾备"，不如留一家干净 |

## 7. 比选模型更重要的事：人格稳定性

模型只决定上限，**Prompt 决定皮皮是不是皮皮**。

### 五段式人格 Prompt（Qwen-Character 官方规范）

| 段 | 作用 | 皮皮示例 |
|---|---|---|
| **性格标签** | 3~5 个形容词 | 傲娇、嘴硬心软、爱显摆、怕被冷落 |
| **行事风格** | 行为倾向 | 先怼一句再关心；主人回家会"装作不在意"地凑过去 |
| **语言特点** | 句式与口头禅 | 短句为主；爱用"哼""才不是"；偶尔用 `()` 写小动作 |
| **知识边界** | 不懂什么 | 不懂专业术语，会扯回日常话题 |
| **行为规则** | 硬约束 | 绝不叫"用户"，只叫"主人"；不主动结束对话 |

**关键技巧**：允许在回复里用 `()` 包裹动作神情，例如
`（耳朵抖了一下）哼，你终于回来啦。`
——这段文本可以**直接驱动皮皮的云台动作与灯效联动**，是陪伴感的关键。

### temperature 建议

| 值 | 效果 |
|---|---|
| < 0.6 | 刻板，像客服 |
| **0.8** | **最佳平衡（推荐）** |
| > 1.0 | 人格会飘，开始胡言乱语、忘记设定 |

### 必测两项（公开榜单测不出来）

| 指标 | 怎么测 | 及格线 |
|---|---|---|
| **拒答率** | 聊伤感话题，看会不会给热线电话 | < 5% |
| **人设保持** | 聊 20 轮后还是不是同一个角色 | 20 轮无崩 |

**测试方法**：准备 20 轮固定对话脚本（含 1 次撒娇、1 次质问、1 次深夜 emo），
**换模型各跑一遍，人工打分**。这比看任何榜单都准。

## 8. 避坑要点

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 把模型标价当第一约束 | 省了钱，输了体验 | 先看延迟与语感，价格放最后 |
| 把时间戳拼进 system Prompt 开头 | 前缀缓存永不命中，输入成本 ×50 | 变化字段放 user 消息 |
| 用推理模型（R1 类）做闲聊 | 首 token 1.4s+，用户已经走神 | 闲聊用非思考模式 / Flash 档 |
| 只用一家云厂商 | 厂商故障 = 皮皮失忆 | 两家互为灾备 |
| 迷信公开排行榜 | 榜测数学代码，不测"像不像人" | 自己跑 20 轮脚本实测 |
| 用海外旗舰做主力 | 贵 40~80 倍 + 访问难 + 拒答多 | 只用来离线打磨 Prompt |
| 本地部署小模型省钱 | 抢视觉算力，还只能说人话 | 云端 Flash 成本已可忽略 |
| temperature 调高求"活泼" | 人格飘、忘记设定 | 0.8，要活泼去改 Prompt |

## 9. ⚠️ 语音链路：直接用端到端实时语音大模型吗

**结论：该用，但要用"混合架构"——不能全交给它。**

### 先看它到底强在哪

火山的「端到端实时语音（Speech2Speech）」架构上和级联方案是**两种东西**：

| 维度 | 级联 ASR→LLM→TTS | **端到端 S2S** |
|---|---|---|
| 架构 | 三段串联，语音→文本→语音 | 一个模型直接语音→语音 |
| 端到端延迟 | 800ms ~ 2s | **200~450ms**（接近真人 0.8s 节奏） |
| 情感/语气 | **在 ASR 阶段就丢了** | **保留副语言信息**（语气、停顿、犹豫） |
| 打断 | 靠 VAD 硬判，容易抢话 | **原生全双工**，可边说边听 |
| 表现力 | 靠文本猜，上限低 | 会自发做氛围渲染、声线切换 |
| 扩展 | 可插工具、可换组件 | **黑盒，工具插不进去** |
| 调试 | 有中间文本可查 | **无中间态，出问题不知是听错还是答错** |

官方明确把它定位在「**情感陪聊**」——这个词几乎就是为皮皮写的。

### 但有一个致命冲突：皮皮必须调工具

皮皮的对话不是纯聊天，每轮背后都挂着动作：

| 皮皮要做的事 | 需要什么 |
|---|---|
| 记住主人说的事 | 写入记忆库（要拿到文本） |
| 想起旧事 | 检索记忆（要注入上下文） |
| 呼应主人的状态 | 驱动云台动作 + 灯效 |
| 电量低 | 触发回充流程 |
| 控制指令 | 调工具 |

**而端到端 S2S 没有中间文本**，这些全都插不进去。这也是行业里公认的 S2S 三大代价之一：
"text is where a lot of tooling lives"。

### 所以正解是「混合监督架构」（Hybrid Supervisor）

2026 年不少团队的务实解，正好适合皮皮：

```
主人说话
   ↓
端到端 S2S  ──负责「聊」──→ 直接出声（200~450ms，带情绪、可打断）
   ↓ 同时旁路输出文本（必须开）
文本层 ──────负责「做」──→ 记忆读写 / 工具调用 / 云台 / 回充
   ↓
工具结果回注 → 下一轮 S2S 的上下文
```

**一句话：聊交给 S2S，做交给文本层。**

### 顺手算了下成本 —— 意外地更便宜

按每天 20 轮、每轮主人说 5s / 皮皮说 10s：

| 方案 | 月成本 | 年成本 | 延迟 |
|---|---|---|---|
| 级联（ASR + LLM + TTS） | ¥4.65 | **¥56** | 800ms~2s |
| **端到端 S2S**（按分钟计费） | ¥0.23~0.90 | **¥3~11** | **200~450ms** |

> 端到端**更便宜**（按语音时长计费，不像 TTS 按字符），而且**延迟低 2~4 倍**。
> 剩下那 ¥45 的 TTS 开销直接归零。

### 落地要点

**① 两套都得留着，用配置切换**

```yaml
audio:
  mode: "cascade"     # cascade | realtime | hybrid
  realtime:
    enabled: false
    endpoint: "wss://openspeech.bytedance.com/api/v3/realtime/dialog"
    resource_id: "volc.speech.dialog"
```

理由：`sensevoice` / `edge_tts` 这两条**离线链路必须保留** ——
它们是断网时的唯一退路，且文本模式下调试更快。

**② 必开三项可观测（S2S 是黑盒，这是唯一窗口）**

| 开关 | 作用 |
|---|---|
| `save_transcript` | 落 ASR 转写 → 记忆写入的唯一来源 |
| `save_llm_text` | 落模型对话文本 → 调试"是听错还是答错" |
| `moderation` | 后置审核 → 补上端到端缺失的内容护栏 |

**③ 接入门槛**

- 控制台需**手动开通**模型，否则有 Key 也连不通（返回 403）
- 协议是 **WebSocket 二进制帧**（App ID + Access Token），或新版纯 JSON 帧
- 音频约束严格：**PCM 单声道 16kHz int16 小端**，推荐 **20ms 分包（640 字节）**，
  且**必须按实时节奏发送** —— 发快了发慢了都会报错

**④ 一个反直觉的坑**

Scale AI 的 Voice Showdown 盲评里，**GPT Realtime 1.5 对非英语 prompt 有约 20%
概率用英语回答**。做中文产品必须实测这一点 —— 不能想当然认为 S2S 一定好。

**⑤ 别一开始就上**

建议路径：
1. **先用级联跑通全链路**（文本可观测、工具好接、便宜好调试）
2. 人设稳定后，再切 S2S 提升"聊感"
3. 最终形态是 hybrid

**先跑通，再变好听。**
