## 1. 为什么是「十字形」

先说清楚「十字形」指的是**轮子怎么摆**，不是**底板什么形状** —— 这两件事经常被混为一谈。

四轮全向底盘的轮心在俯视投影上的排布只有两种正交方案：

| 布局 | 轮心构成的多边形 | 相邻臂夹角 | 相邻轮轴心距 |
|---|---|---|---|
| **矩形（常规方形底盘）** | 正方形 / 长方形 | 90°（轮心连成矩形边） | = 轮距 track |
| **十字形（本设计）** | 菱形（旋转 45° 的正方形） | **90°（轮心连成十字四臂）** | = **track / √2** |

**一句话区分**：把方形底盘的四个轮子分别**往外挪到底板四条边的中点外侧**，就变成十字——轮子从「四个角」移到「四条边」，方向不变，整个轮心多边形转了 45°。

> 皮皮的底盘就是一个**圆柱（小垃圾桶造型）**，四个轮子从柱体外侧四个方向伸出来，从正上方看正好是「十」字。这也是「十字布局」的由来 —— 不是它发明了什么特殊运动学，而是**圆柱外壳 + 四轮 90° 均布**这个形态。

### 十字布局换来什么、付出什么

| 维度 | 十字形 | 矩形 | 皮皮怎么看 |
|---|---|---|---|
| **壳体适配** | 天然贴圆柱壳 | 需要方形壳 | ✅ 皮皮是陪伴机器人，圆柱壳才像「小宠物」，方形像「小车」 |
| **转向时的车身扫过** | 圆柱扫过 = 自身 | 正方形对角线扫过 = 边长×1.414 | ✅ 圆柱壳不会「甩角」蹭到桌腿 |
| **绕 Z 力矩臂** | track/2 | √((track/2)²+(wb/2)²) = track/√2 | ❌ 十字小 **29.3%** |
| **相邻轮间距** | track/√2 | track | ❌ 十字小 **29.3%** → 要放大尺寸补偿 |
| **对地压强分布** | 四点均布于圆周 | 四点均布于矩形 | 基本等价 |
| **撞击方向对称性** | 四方向完全对称 | 也是四方向对称 | 等价 |
| **造型识别度** | 高（像宠物） | 低（像小车） | ✅ 见上 |

**结论**：十字布局唯一的实质代价是**力矩臂缩小 29.3%**，导致（a）原地旋转扭矩需求上升、（b）相邻轮更容易干涉。这两点都能靠**加大 footprint** 补回来 —— 本文取 **240×240mm**，就是把 track 从「刚好够」的 150mm 提到 240mm。

> **代价的量化**：十字 240×240 的力矩臂 = 120mm；要拿到同样 120mm 力矩臂，矩形布局只需要 340/√2… 反过来说，**矩形 170×170 的力矩臂就等于十字 240×240**。所以十字必须做大一圈才不吃亏 —— 本文已经做大了。

## 2. 整机重量分解与重心

| 层 | 部件 | 质量 | 层高（距底盘上表面） |
|---|---|---|---|
| L1 底盘层 | 十字底板 + 4 电机 + 4 麦轮 | **1.89 kg** | +3 mm |
| L1 挂载 | 3S 电池组（18650 3S2P） | **0.34 kg** | **−18 mm**（下挂） |
| L2 电控层 | C30D + 线材 + 电源分配 + DC-DC | **0.16 kg** | +34 mm |
| L3 主控层 | N100 无风扇工控机（含 SSD） | **0.55 kg** | +72 mm |
| L4 头部层 | 云台支架 + 2×MG996R | **0.20 kg** | +96 mm |
| L4 头部层 | 头部外壳 + 摄像头 + 麦阵 + 灯带 | **0.15 kg** | +128 mm |
| | **合计** | **3.29 kg** | |

### 重心计算

以底盘上表面为 z=0，各层质量加权：

```
z_cg = Σ(mᵢ·zᵢ) / Σmᵢ
     = (1.89×3 + 0.34×(−18) + 0.16×34 + 0.55×72 + 0.20×96 + 0.15×128) / 3.29
     = (5.67 − 6.12 + 5.44 + 39.6 + 19.2 + 19.2) / 3.29
     = 82.99 / 3.29
     ≈ 25.2 mm（距底盘上表面）
```

**加上轮子半径（轮心在底盘下 30mm，轮心即底盘上表面 −30mm）**：

```
整车重心离地高 h_cg ≈ 25.2 + 30 = 55.2 mm
```

> **电池下挂是这里的关键设计。** 如果电池放在底板上方（z=+20），重心会上抬到 ≈ 68mm；下挂到 z=−18，重心压到 ≈ 55mm，**降了 19%**。麦轮小车最怕急停/急转时翘轮，这一下是白赚的。

## 3. 几何设计（含推导）

### 3.1 麦轮占宽 → 相邻轮最小间距

| 参数 | 值 | 来源 |
|---|---|---|
| 麦轮标称直径 | 60 mm | 选型（`HARDWARE.md` §7.3） |
| 轮毂宽（不含辊子） | 31 mm | 60mm 麦轮常规值 |
| 单侧**辊子外凸** | 9 mm | 辊子轴线 45° 斜装，绕轮缘甩出 |
| **单轮总占宽** | 31 + 2×9 = **49 mm** | |
| 安全间隙 | 20 mm | 装配误差 + 辊子自转空间 |
| **相邻轮轴心距下限** | 49 + 20 = **69 mm** | |

> ⚠️ **这里最容易踩坑**：很多人按「轮毂 31mm」算间距，装完发现**斜对角的辊子互相啃**。辊子是 45° 斜的，它在水平面上的投影比轮毂宽 —— 必须按 49mm 算。

### 3.2 十字几何 → 轮距下限

十字布局相邻两轮夹角 90°，轴心距 = 等腰直角三角形的斜边：

```
相邻轮轴心距 = √((track/2)² + (wheelbase/2)²)
十字对称（track = wheelbase）时： = track / √2
```

令 `track/√2 ≥ 69mm`：

```
track ≥ 69 × √2 ≈ 97.6 mm   ← 纯几何下限（极其紧凑，会翻）
```

这个尺寸当然不能用 —— 太窄了，侧翻裕度几乎为零。**真正决定尺寸的是稳定性**（见 §8.3）和**中心枢纽的容纳能力**（电池包 + C30D）。

### 3.3 中心枢纽尺寸 → 反推轮距

枢纽圆盘必须同时塞下：

| 部件 | 尺寸 | 需求半径 |
|---|---|---|
| 18650 3S2P 电池包 | 45 × 73 × 65 mm | √(45²+73²)/2 = **42.9 mm** |
| 21700 3S2P 电池包 | 50 × 78 × 74 mm | √(50²+78²)/2 = **46.3 mm** |
| C30D 板 | ~90 × 60 mm（立装于枢纽侧面） | — |

取 **枢纽半径 62 mm（直径 124 mm）**，留 13mm 余量给固定孔和走线。

枢纽到轮心的距离 = track/2 − hub_r，要在容纳「电机 + 减速箱 + 编码器」的长度（约 55mm）之后还有剩余。取 **track/2 = 120mm** → 电机腔有 120 − 62 = **58 mm**，刚好。

**选定：track = wheelbase = 240 mm。**

### 3.4 最终几何参数表

| 参数 | 值 | 备注 |
|---|---|---|
| 轮距 track | **240 mm** | = 轴距（十字对称） |
| 轴距 wheelbase | **240 mm** | |
| 相邻轮轴心距 | **169.7 mm** | 需求 ≥69 mm，**余量 2.46×** ✅ |
| 力矩臂（绕 Z） | **0.170 m** | √(120²+120²) |
| 中心枢纽半径 | **62 mm** | 直径 124mm |
| 十字臂宽 | **58 mm** | 电机支架安装面 |
| 底板厚度 | **4.0 mm** | PETG / 6061 铝 |
| 电机腔净深 | **58 mm** | track/2 − hub_r |
| **车体外接圆直径** | **300 mm** | = track + 轮径 = 240 + 60 |
| **实际占地（含辊子）** | **≈ 318 mm** | + 辊子外凸 2×9 |
| 麦轮总高（车底离地） | 30 mm | = 轮半径 |

> **和桌面版的兼容性**：皮皮头部外壳直径约 160mm，**小于底盘 300mm**，所以从正上方看完全被底盘盖住 —— 视觉上就是「一个圆墩墩的底座顶着一个小脑袋」，符合皮皮的形态。桌面版（无底盘）时头部直接落地，总高 ≈ 180mm。

## 4. 麦轮左旋 / 右旋布置

### 4.1 L 和 R 的区别

麦轮的辊子与轮毂轴线成 45°，但**倾斜方向有两种手性**：

| 类型 | 辊子俯视走向 | 滚动时侧向力方向 |
|---|---|---|
| **L（左旋）** | `/`（右上 → 左下） | 偏**左** |
| **R（右旋）** | `\`（左上 → 右下） | 偏**右** |

L 和 R 是**镜像件，不可互换**。四个轮子装成 `4L` 或 `3L1R` 都转不动横移。

### 4.2 皮皮采用的布局：X 型（L-R-R-L）

```
              车头 (前)
                 ▲
                 │
        ┌────────┴────────┐
        │                 │
   ╔════╧════╗       ╔════╧════╗
   ║  L 左前 ║       ║  R 右前 ║
   ╚════╤════╝       ╚════╤════╝
        │                 │
   ─────┼───── ● ─────────┼─────   ← 十字臂（4 条，夹角 90°）
        │    中心        │
   ╔════╧════╗       ╔════╧════╗
   ║  R 右后 ║       ║  L 左后 ║
   ╚════╤════╝       ╚════╤════╝
        │                 │
        └────────┬────────┘
                 │
                 ▼
              车尾 (后)

        对角同向：FL=L, RR=L  |  FR=R, RL=R
        相邻反向：FL/RR↔FR/RL 交替
```

**规则：对角同向、相邻反向。** 左前、右后为 **L**；右前、左后为 **R**。

> **为什么必须是 X 型而不是 O 型？**
> O 型（同侧同向：左侧全 L、右侧全 R）理论上也能全向移动，但**原地旋转时代入运动学会出现侧向力不完全抵消**，实测表现是「转的时候往外飘」。X 型对角同向，旋转时四轮侧向分力两两对消，**纯扭矩、不漂移**。这是 AGV 和赛事机器人的行业标准，90% 以上四轮麦轮底盘都是 X 型。

### 4.3 L / R 的安装检查（装完必做）

1. **俯视看辊子**：把小车摆正（车头朝你），左前轮和右后轮的辊子中轴线**指向车体外侧**（斜向外），右前和左后**指向内侧**。
2. **手感验证**：用手分别拨动同一侧的辊子，左前和右后的辊子「顺转方向」应该一致，与右前/左后相反。
3. **纸上验证**：整车放玻璃板上，四个轮着地点应共面，无一轮悬空（麦轮对共面极敏感，悬空一个轮 → 运动学崩）。

### 4.4 十字布局的运动学公式（已写入 C30D 固件）

标准麦轮逆运动学，`lx = ly = 120mm`（十字对称）：

```python
# 输入：vx（前后, m/s） vy（横移, m/s） wz（自转, rad/s）
# 输出：四个轮子角速度（rad/s），FL/FR/RR/RL
w_FL = (vx − vy − (lx+ly)·wz) / r
w_FR = (vx + vy + (lx+ly)·wz) / r
w_RR = (vx + vy − (lx+ly)·wz) / r
w_RL = (vx − vy + (lx+ly)·wz) / r      # r = 0.030 m
```

**验算过的四组典型指令**（`chassis.scad` 同款参数）：

| 指令 | FL | FR | RR | RL | 车身行为 |
|---|---|---|---|---|---|
| `vx=0.5, vy=0, wz=0` | 159 | 159 | 159 | 159 RPM | 直行 |
| `vy=0.5, vx=0, wz=0` | 159 | 159 | 159 | 159 RPM | **横移** |
| `wz=1.0, vx=vy=0` | 76 | 76 | 76 | 76 RPM | **原地转** |
| `vx=vy=0.5, wz=0` | 0 | 318 | 318 | 0 RPM | **斜向 45°** |

> **注意直行和横移的轮速数值完全一样**（都是 `|v|/r`），区别只在**转向**（正负号）。这就是麦轮的对称性 —— 皮皮从「前进」切到「横移」，四个电机的转速模长不变、只是反转，**响应极快、几乎无过冲**。这也是 `Gesture.SIDE_STEP`（侧身滑开）能做得那么干净的原因。

> **斜向 45°（`vx=vy`）时对角两轮停转、另两轮 2× 速度** —— 这是 X 型的经典特征，也是 X 型的能量优势：斜移时只用两个电机。

### 5.2 三种规格怎么选

**⭐ 首选：18650 通用电芯 · 3S2P（¥167 / 7.0Ah / 2.5h）**

- **为什么是它**：18650 是**全世界最通用的锂电规格**，单节 ¥20~25，坏了单换一节；**便利店/五金店都能补**。
- **容量够不够**：活跃工况 2.5h、轻度 6.0h、纯待机 14.9h。陪伴机器人单次交互 10~30 分钟，**一周充一次**完全够。
- **放电够不够**：20A 持续 vs 峰值需求 4.25A → **4.7× 余量**，电池几乎不发热。
- **重量最轻**：0.34 kg，比 21700 方案轻 0.14 kg —— 全部在最底层，等同于把重心再压低。

**进阶：21700 通用 · 3S2P（¥227 / 10.0Ah / 3.5h）**

- 同样体积塞进 43% 更多电量，**续航 3.5h**。
- 单节 ¥32，比 18650 贵 45%，但**每 Wh 成本反而更低**。
- 缺点：**没有 18650 通用**，坏了要网购等快递；重量 +0.14kg。
- **适合**：确定要长时间移动（比如展会/陪伴老人全天走动）。

**不推荐：26650 / 动力电芯**

- **26650** 单节 92g，3S2P 就 0.61kg，同样 10Ah 却比 21700 重 27%、贵 34%。除非你手头现成有。
- **动力电芯**（20A 单节）在皮皮身上**完全用不上**：峰值 4.25A，通用电芯 10A/节 = 20A/包已经是 4.7× 余量。花 ¥263 买 40A 放电能力，是买了个永远不用的参数。
- **例外**：如果以后要加**升降柱/机械臂**（大电流舵机），再换动力电芯。

### 5.3 3S2P vs 3S3P 怎么定

| | 3S2P | 3S3P |
|---|---|---|
| 并联数 | 2 列 | 3 列 |
| 仓宽 | **45 mm** | 65 mm |
| 枢纽适配 | ✅ 轻松塞进 124mm 圆 | ⚠️ 挤，需要把 hub_r 加到 70mm |
| 重量 | 0.34 kg | 0.48 kg |
| 续航 | 2.5 h | 3.7 h |
| 价格 | ¥167 | ¥233 |

**结论：先做 3S2P。** 3S3P 的 67mm 仓宽会把枢纽撑到半径 70mm，整机 footprint 得跟着放大，**为了 1.2h 续航不值得**。真要长续航，直接上 21700 3S2P（同样 10Ah，仓宽只有 54mm）。

## 6. 电池仓设计

### 6.1 结构

电池**下挂**在十字底板正下方，占据中心枢纽的投影区：

```
        ┌─────────── 十字底板（z=0，4mm 厚）───────────┐
        │                                              │
        │        ┌────────────────────┐                │
        │        │  电池支架（3D 打印） │                │
        │        │  ┌──┬──┬──┐        │  ← 3 节串联    │
        │  z<0  │  │  │  │  │        │    (3S)       │
        │        │  ├──┼──┼──┤        │               │
        │        │  │  │  │  │        │   2 列并排    │
        │        │  └──┴──┴──┘        │    (2P)       │
        │        └────────────────────┘               │
        └──────────────────────────────────────────────┘
                     ↑ 离地间隙 12 mm（含 4mm 底板）
```

### 6.2 尺寸（18650 3S2P）

| 项 | 值 | 说明 |
|---|---|---|
| 电芯直径 | 18.4 mm | 18650 实测（非 18.0） |
| 电芯长度 | 65.2 mm | |
| 支架壁厚 | 3 mm / 边 | PETG 打印 |
| **包尺寸 W×L×H** | **45 × 73 × 65 mm** | W = 2 列 +2mm 间隙，L = 电芯轴长 + 8mm，H = 3 节串叠 +2×2mm |
| 挂载深度 | 26 mm | 底板下表面往下 |
| BMS | 3S 40A 均衡板，40×25×8 mm | 贴在支架侧面 |
| 接头 | XT60（放右侧，朝外） | 拔插方便 |

### 6.3 兼容 21700 / 26650

OpenSCAD 模型里把 `BATT_CELL` 改成 `"21700"` 或 `"26650"`，支架自动重算：

| BATT_CELL | PACK_W | PACK_L | PACK_H | 需要的 hub_r |
|---|---|---|---|---|
| `"18650"` | 45 | 73 | 65 | ≥ 42.9 mm ✅（现 62） |
| `"21700"` | 50 | 78 | 74 | ≥ 46.3 mm ✅（现 62） |
| `"26650"` | 61 | 73 | 90 | ≥ 47.8 mm ✅（现 62） |

> **三种规格都能塞进现有 62mm 半径枢纽**，所以**改一行变量就能换电池规格**，不用重新设计底盘。这是参数化建模的价值。

### 6.4 为什么不下挂整块底板

- 下挂电池包只占**中心投影**，四周仍然留空 → 麦轮辊子不会被挡住。
- 底板翻转装电机时，电池包是**独立件**，可以先拆下来，装配不打架。
- **换电池 = 松 2 颗 M3 螺丝 + 拔 XT60**，30 秒换完。做两块电池轮换用，比加容量划算。

### 走线原则

| 线 | 路径 | 要点 |
|---|---|---|
| 电池 → C30D 电源 | 底板中心孔 → L2 | **14AWG 硅胶线**，短路电流大，不能细 |
| C30D → 4 电机 | 沿十字臂内侧走 | 编码器线**远离**电源线（防串扰），分开两侧 |

## 8. 动力学复核（扭矩 / 续航 / 防翻）

### 8.1 扭矩余量

```
需求：加速 0.8 m/s²（0.5m/s 上限下的急速起步）
整机 3.29 kg → 合力需求 = 3.29 × 0.8 = 2.63 N
单轮需求推力 = 2.63 / 4 = 0.66 N
单轮需求扭矩 = 0.66 N × 0.030 m = 0.0197 N·m = 0.201 kg·cm
```

| 指标 | 值 | 需求 | 余量 |
|---|---|---|---|
| MG513 额定扭矩 | 2.0 kg·cm | 0.201 | **9.9×** ✅ |
| MG513 堵转扭矩 | 9.0 kg·cm | 0.201 | **44.7×** ✅ |

> **麦轮实际损耗远高于普通轮**（辊子滑动摩擦），上表是理想值。**业界经验取 3~5× 打折**，即便如此**额定余量仍有 2.0~3.3×，安全**。这就是为什么 `HARDWARE.md` 强调「麦轮不能配弱电机」—— 皮皮这个 9.9× 是**算过麦轮损耗后**的结论。

### 8.2 续航

| 工况 | 电流 | 18650 3S2P (7.0Ah) | 21700 3S2P (10.0Ah) |
|---|---|---|---|
| **待机**（主控 + 麦阵 + 灯效长亮） | 0.4 A | **14.9 h** | 21.2 h |
| **轻度**（偶发对话 + 少量移动） | 1.0 A | **6.0 h** | 8.5 h |
| **活跃**（持续对话 + 边移动边看） | 2.4 A | **2.5 h** | 3.5 h |
| **全负载**（4 电机堵转） | 4.25 A | 1.4 h | 2.0 h |

> 计算含 **85% 放电效率**（不把电池放到 3.0V 截止，保护寿命）。
> **皮皮的典型使用日**：早上 2 次对话 + 下午跟着走 20 分钟 + 晚上 30 分钟聊天 ≈ **1.5~2.0h 活跃** → **18650 3S2P 刚好够一天**，每晚充电。

### 8.3 侧翻稳定性

```
临界横向加速度 a_tip = g × (轮距/2) / h_cg
                     = 9.81 × 0.120 / 0.055
                     = 21.4 m/s²
```

| 项 | 值 |
|---|---|
| 轮距 | 240 mm |
| 重心高 h_cg | 55.2 mm |
| **临界横向加速度** | **21.4 m/s²** |
| 实际横移加速度上限 | 1.0 m/s²（配置里 `max_linear_accel` 量级） |
| **安全裕度** | **21.4×** ✅ |

> **21 倍裕度意味着：皮皮以最大加速度横移时，离侧翻还差一个数量级的加速度。**「电池下挂 + 240mm 宽轮距」这两个设计的贡献各占一半 —— 如果电池上置（h_cg=68mm）、轮距只有 180mm，裕度会掉到 11.6×，虽然仍然安全，但被撞一下/上个小坎就没那么从容了。

> **真正的翻车场景不是横移，是「上台阶 + 急转」复合**。麦轮过电梯缝、门槛时单轮悬空，此时只剩三轮着地，稳定性下降。**规避**：固件里对 `|vy|` 加软限幅，转弯时降速（已在 `wheeltec.py` 的 `max_linear` / `max_angular` 配置里预留）。

## 12. 自动回充与充电桩

> **本节回答**：皮皮怎么自己找到桩、怎么精准对进去、桩上要什么电路；
> 以及**能不能用无线充电**（§12.6 给明确结论）。

### 12.1 为什么麦轮底盘天生适合回充

回充的本质难题是**把车体的两个量同时归零**：离桩的距离、相对桩的偏角。
差速底盘只有 `(vx, wz)` 两个自由度，这两个量**耦合**——想转正就会偏离、
想靠近就会撞歪。工程上只能：

- 规划 S 形倒车曲线（要精确标定，换地面就打滑）；
- 或者反复「前进 → 量一下 → 修正 → 后退」，慢且像新手停车。

麦轮有 `(vx, vy, wz)` **三个正交自由度**，于是可以把对接**解耦**：

| 段 | 控制量 | 做什么 | 不做什么 |
|---|---|---|---|
| ① 缩距 | `linear.x` | 沿桩法线靠近 | 不管航向、不管心偏 |
| ② 调心偏 | `linear.y` | 纯横向平移 | 不动航向、不动距离 |
| ③ 调角偏 | `angular.z` | 原地旋转 | 不动位置 |

**三段互不干扰 → 三个独立单变量闭环，各配一个 P 控制器 + 死区就收敛。**
不需要 MPC、不需要轨迹规划、不需要额外标定。

> **关键结论：C30D 固件一行都不用改。** 因为这三种运动本来就是 `/cmd_vel`
> 自带的标准字段（`Twist.linear.x` / `.y` / `.angular.z`）。别的底盘要做
> 回充往往得在固件里加专用回充模式；皮皮不用。

### 12.2 引导方式：远程视觉 + 近程红外

行业里回充引导方案有五种，各有取舍：

| 方案 | 精度 | 成本 | 需要算力 | 适用距离 | 皮皮适合吗 |
|---|---|---|---|---|---|
| 单种红外 | 差（方向性弱，易受干扰） | 极低 | 无 | <1 m | 只做近程可以 |
| **红外 + 视觉融合** | **高（<2 cm）** | **低** | **低** | **0.3~3 m** | ✅ **采用** |
| 激光雷达识别凹凸特征 | 高 | 高 | 高（点云算法） | 2~5 m | ✗ 皮皮没装雷达 |
| QR / AprilTag 视觉 | 高 | 极低 | 中 | 0.5~4 m | ✅ 采用（作远程段） |
| 超声波 | 差（波束宽） | 低 | 无 | <2 m | 只作避障 |

**皮皮的选择：`AprilTag 视觉（远程） + 红外双发双收（近程）`**

理由就是**复用已有硬件**：

- 皮皮已有 1080P 无畸变 UVC 摄像头（`HARDWARE.md` §4），远程段不新增任何硬件，
  只在桩面贴一张 AprilTag 贴纸（¥1）。
- 近程段只需 2 只红外发射管（装桩上）+ 2 只红外接收管（装车尾），
  合计 **¥30 以内**。不需要激光雷达、不需要加算力。

```
【远程段】3.0 m ~ 0.35 m           【近程段】0.35 m ~ 0 m
  车头摄像头看桩面 AprilTag           车尾双红外接收管  ← 桩面双发射管
  → 解算 相对位姿 (x, z, θ)           → 解算 横向偏差 + 航向偏差
  → 走 vx（只缩距）                    → 走 vx / vy / wz 三段闭环
```

> **为什么近程要换成红外？** 距离越近，AprilTag 在画面里越大、越容易出框
> （皮皮是**倒车**进桩，摄像头在车头、朝外，最后 35cm 根本看不见桩）。
> 红外不受此限制：发射管装在桩面、接收管装车尾，正对着，越近信号越强。
> 而且红外能**直接给出横向偏差**（左右两个接收管的信号强度差），
> 这正是麦轮 `vy` 那一路最需要的量。

> **红外精度账**（已验算）：接收管视场角分辨约 5°，三角定位横向误差
> ≈ 距离 × 角度分辨 → 0.35m 处约 **±31 mm**，0.10m 处约 **±9 mm**。
> 配合 `±8 mm` 死区和桩口的机械导引斜板（±56 mm 容差），**够用**。
> 远程段交给视觉，所以不需要红外在 1m 外也准。

### 12.3 状态机

`src/pipi/orchestration/dock.py` 实现的完整状态机：

```
                    battery ≤ 25%
                    或 闲置 ≥ 20min
   IDLE ────────────或 到点 23:30 ────────────▶ SEEK
     ▲                                            │ 看到 AprilTag
     │ 充满                                        ▼
  CHARGING ◀──触点闭合+有电流── DOCKED ◀──── APPROACH
     │                            ▲              │ 距离 ≤ 0.35m
     │ 触点脱离                    │ 三段全进死区   ▼
     └──────────────▶ SEEK       ALIGN ◀──────────┘
                                  │ 超时(25s)
                                  ▼
                            SEEK（冷却 15 拍，重试）
                                  │ 累计 > 3 次
                                  ▼
                                 FAIL
     触点闭合但 10s 无电流 ─────▶ FAULT
     有人靠近(<0.8m) ──────────▶ 暂停让路（状态不变）
```

**几个设计细节，都是踩坑换来的：**

1. **失败后必须"冷却"再重试。** 第一版失败后直接回 `SEEK`，而感知层
   的观测还是旧的（车仍歪在桩前、红外读数没变），于是
   `SEEK → APPROACH → ALIGN` 一拍之内走完，**同一个失败瞬间复现**，
   `retries` 永远累加不到上限，控制器在 ALIGN/SEEK 之间抖动。
   现在失败后进 15 拍冷却，给感知刷新时间、也给自己机会退出几何奇异位置。

2. **P 控制增益要在死区附近"软着陆"。** 第一版 `wz_kp=2.0` 配 8° 航向偏差，
   一拍就转过 `2.0 × 8° = 16°`，直接冲到 **−8°**，对称振荡、永不收敛（极限环）。
   现在死区 3 倍范围内按 `|e|/(死区×3)` 线性压增益（下限 0.15），
   实测 5 拍内收敛到死区内。

3. **近场不能"锁死 vx"，只能"减速爬行"。** 第一版写「距桩 <60mm 直接 `vx=0`」，
   但到位死区是 **12mm** —— 车停在 60mm 处**永远满足不了到位条件**（收敛死角）。
   现在改成近场把 `vx` 压到 0.02 m/s，把最后几十毫米走完。

4. **未对正时禁止前进。** 横向或航向任一没进死区 → `vx` 强制为 0，
   先纠正姿态。避免"歪着撞桩"把触点弹片顶坏。

5. **有人靠近就停。** 陪伴机器人撞人比充不上电严重得多。
   距离 <0.8m 时整段暂停（状态不变），人走开自动恢复。

### 12.5 充电桩机械设计

参数化模型：`hardware/dock.scad`（`PART=0` 总装 / `1` 桩体 / `2` 底板投影 / `3` 导引板）。

```
        ← 车体从这边倒进来                    ┌── 桩体后缘（触点面板）
                                              │
   ╲                                        ┌─┴──────────────┐
    ╲  导引斜板（±22°）                       │  IR  ●    ●  IR │ ← 双红外发射管
     ╲                                      │      ●  ●       │ ← 双触点铜柱
      │   ┌──────────────────────────┐      │                 │
      │   │   中央开口 210mm          │      │                 │
      │   └──────────────────────────┘      │                 │
     ╱                                       └─────────────────┘
    ╱  导引斜板                              桩体 260 × 120 × 48 mm
   ╱
```

| 参数 | 值 | 为什么 |
|---|---|---|
| 桩体外形 | **260 × 120 × 48 mm** | 低矮（48mm），不挡视线，皮皮像"钻进去" |
| 中央开口 | **210 mm** | 车尾约 150mm → 单侧 30mm 余量 |
| 导引口外张 | **±56 mm**（含开口余量） | 皮皮只要大致对准就能被"喂"进去 |
| 触点高度 | **46 mm**（离地，竖直面） | 避开麦轮、避开地面灰尘 |
| 两触点间距 | **22 mm** | 爬电距离 12mm（>8mm 安全线） |
| 红外管位置 | 触点两侧 **±40 mm** | 三角定位基线 |
| 壁厚 | 4.0 mm（PETG / 可切铝） | 承重不大，打印即可 |

**为什么触点是"竖直面"而不是"地面"？** 这是回充设计里最容易被忽略的一点：

| | 地面触点 | **竖直面触点（采用）** |
|---|---|---|
| 积灰 | 灰尘直接落在触点上 | 竖直面不积灰 |
| 车轮压过 | 麦轮**会压到**触点 | 麦轮走两侧，不碰触点 |
| 自清洁 | 无 | 每次对接是"顶"进去，**有刮擦自清洁效果** |
| 排水 | 泼水会泡触点 | 竖直面不积水 |

**电气设计**：

| 项 | 值 | 说明 |
|---|---|---|
| 输入 | 12.6V / 3.5A 恒流（**0.5C**） | 18650 3S2P 7.0Ah → 0.5C = 3.5A，功率约 44W |
| 充满电压 | 12.6V 恒压 → 转涓流 | 3S 满充点 |
| 触点材料 | 铜镀镍弹片（弹簧行程 3mm） | 耐插拔、抗氧化 |
| 保护 | 防反接二极管 + 自恢复保险丝 | 防桩端接反、防短路 |
| 接地 | 桩体前缘铜片先接地泄静电 | 对接瞬间不放电火花 |

> **为什么不 1C 快充（7.0A）？** 7A 会让电芯温升明显、循环寿命掉得快；
> 而且皮皮是「回家过夜充」的场景，**2 小时充满和 1 小时充满对用户没区别**。
> 0.5C 换来的电池寿命更划算。

> **接触电阻发热账**（已验算）：3.5A 电流下，接触电阻 20mΩ → 单点发热
> **0.24W**，两点 0.49W，可忽略。这也是触点方案相对无线的核心优势之一
> （见 §12.6）——**损耗只有毫瓦级，不产生"要散的热"**。

### 12.6 能不能用无线充电？—— 结论与判据

**结论：技术上完全可以，但对皮皮不推荐作为首选。**
理由不是"无线不好"，而是**无线擅长的场景皮皮一个都不占**。

#### 效率与发热：无线多出来的损耗是实打实的

皮皮充电功率约 44W（12.6V × 3.5A），三种方案的账：

| 方案 | 典型效率 | 输入功率 | **损耗（全变热）** | 充满时间 |
|---|---|---|---|---|
| **有线触点** | **90~95%** | 46.3 W | **2.3 W** | 30~60 min |
| 无线·磁共振 | 80~90% | 48.9~55 W | **4.9~11 W** | 60~120 min |
| 无线·电磁感应（Qi 类） | **70~80%** | 55~62.9 W | **11~19 W** | 45~120 min |

Qi 标准本体是 5~15W、距离 ≤4cm —— 皮皮需要 44W，**超出 Qi 常规档位**，
得用专门的 40~60W 无线充电模组（成本上去了）。

> **关键问题：这 11~19W 的损耗在皮皮身上是负担。**
> 皮皮的底盘是**密闭的**（要防尘、防宠物毛），线圈和接收板都在底板下方，
> 本来就靠底盘金属板导热。多出十几瓦的持续发热，要么设计散热通道
> （破坏密封性），要么让电芯长期在偏高温度下充电（**锂电寿命杀手**）。
> 而触点方案的损耗是 **2.3W**，还是分散在两个小触点上，**根本不需要专门散热**。

#### 对齐精度：无线反而要求更高

| | 允许偏移 | 允许偏角 |
|---|---|---|
| **触点（弹簧弹片）** | **±15 mm 以上**，靠弹片行程吸收 | ±10° 以上 |
| 无线（Ø40 线圈） | **±13 mm 以内**效率就开始掉 | **±5° 以内**，偏角对耦合影响极大 |

线圈外径 40mm 时，偏移超过约 **1/3 外径（13mm）** 效率断崖式下跌。
也就是说 **无线充电对"对得准不准"的要求，比触点更高** ——
这跟我们"无线 = 随便放"的直觉正好相反。

而 §12.1 的三段式控制之所以够用，正是因为**触点方案容差大**。
换成无线，等于把对接精度要求反向提高一档，反而更容易失败。

#### 成本与寿命

| | 触点方案 | 无线方案 |
|---|---|---|
| 桩端 | 弹片 + 二极管 + 保险丝 ≈ **¥20** | 40W 发射模组 ≈ **¥120~300** |
| 车端 | 触点座 ≈ **¥10** | 接收模组 + 线圈 ≈ **¥80~200** |
| 合计 | **≈ ¥30** | **≈ ¥200~500** |
| 寿命瓶颈 | 触点磨损（铜镀镍，实测 万次量级） | 线圈/电容老化、发热累积 |
| 维护 | 偶尔擦触点 | 无接点，免维护 |
| 恶劣环境 | 潮湿需防护 | **可全密封**（防水防尘） |
| 待机功耗 | 0 | 发射端需持续探测（数 W） |

#### 那什么时候该上无线？

无线的优势在下面这些场景才真正兑现。**对照皮皮的实际情况**：

| 无线明显更划算的场景 | 皮皮符合吗 |
|---|---|
| 24h 高稼动率（触点磨损快、维护成本高） | ❌ 皮皮每晚充一次 |
| 多台机器人共用充电区（触点规格难统一） | ❌ 单台 |
| 恶劣环境：潮湿、粉尘、油污、户外 | ❌ 家庭室内地面 |
| 需要**完全密封**（防水冲洗 / 食品厂 / 医院消毒） | ❌ 无需冲洗 |
| 有易燃气体/粉尘，怕触点打火 | ❌ 无 |

**皮皮的场景（家庭室内、单台、每晚充一次、地面干净）把触点方案的优势全部命中，
把无线的优势全部避开。**

#### 什么条件下改用无线

不是"永不"，而是**满足以下任一条件就值得切**：

1. **底盘要做得完全密封**（比如以后要加"可水洗"卖点，或加湿器旁使用）；
2. **有多台皮皮**在同一充电区轮换（触点规格不统一、磨损集中在一个桩上）；
3. **充电桩位置固定且要求"零维护"**（比如装在地毯下、家具底，够不着擦触点）；
4. 充电功率降到 **10W 以下**（比如只做待机补电），落入 Qi 标准档位，
   模组便宜、效率影响也小。

> **过渡方案（推荐做法）**：先按 §12.5 的触点方案做。
> 触点座和无线接收线圈占用的是**同一个位置、同一块底板区域**，
> 底板留好安装孔位即可 —— 将来想切无线，换一块底板、去掉弹片就行，
> **车体结构和 `DockController` 一行都不用改**（因为对接控制逻辑完全一样，
> 只是"最后 10mm 用不用顶进去"的差别）。这就是把对接**解耦成三段**
> 的另一个好处：**换了充电方式，控制策略不变。**
