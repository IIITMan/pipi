# 皮皮・可成长性设计方案 v0.2

> 向「原生机器人 IP」演进 —— 让皮皮像二白一样：不是出厂即成品，而是 "养出来的"。
> 每一次真实互动都在改写它：关系变深、性格有记忆、表达有来历、回忆会沉淀。
> 版本：0.2 (可实施版)・2026-10-08・在 0.1 草案基础上补充竞品设计依据、引擎详细设计、数据表与验收用例



***

## 0. 设计总纲

**核心命题**: 皮皮的价值不在于 "功能多", 而在于 "只属于你"。一个克隆皮皮无法取代你的皮皮。

**成长的定义**: 四个维度 —— 关系 × 性格 × 记忆 × 表达 —— 的持续演化，全部由真实相处驱动 (不是定时器、不是随机数)。相处是唯一的输入，成长是输出。

### 0.1 设计依据 (竞品调研・2026-10)



| 参照                          | 关键机制                                                                                            | 对皮皮的启示                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |

## 1. 成长四维框架

### 1.1 关系成长 —— 从陌生人到家人 (主刻度)

**阶段机**:



| 阶段 | 名称       | 进入条件 (全部满足)                   | 可塑性  | 表达权限                      |
| -- | -------- | ----------------------------- | ---- | ------------------------- |
| S1 | 婴儿 (未认主) | 初始状态                          | 1.00 | 客气、克制、不主动打扰               |
| S2 | 幼儿       | 完成认主 + 累计 ≥5 天有互动             | 0.60 | 开始主动关心 (频率红线内)            |
| S3 | 少年       | 累计 ≥30 天互动 + ≥2 个里程碑          | 0.35 | 解锁身体玩笑、轻度毒舌               |
| S4 | 成熟       | 累计 ≥90 天 + ≥1 个纪念日 + 好感度 ≥ 阈值 | 0.15 | 解锁危机话术 (装傻式偏心)、最浓的粘人 / 傲娇 |

*可塑性 = 偏好 / 表达演化步长系数 (见 §2.3),S1\~S4 数值为初始建议，待实测调参。*

**推进规则 (硬性门槛，防速成)**: 阶段推进必须全部条件满足，不可跳跃、不可刷。回落:≥30 天不联系缓慢回落一级，但不低于 S2 (与好感度底价一致：认过主不会变回陌生人)。

**里程碑清单**(命中即写入 `growth_milestones`, 同时沉淀为 commitment 型记忆，永不遗忘):



| 编码 | 事件         | 触发条件                     | 记忆类型              |
| -- | ---------- | ------------------------ | ----------------- |
| M1 | 认主         | 人脸或声纹首次匹配成功              | identity          |
| M2 | 记住第一个喜好    | profile.likes 首次非空       | preference(story) |
| M3 | 第一次主动关心被回应 | proactive 成功且用户 10 分钟内回复 | commitment(story) |
| M4 | 第一个纪念日     | 相遇满 30 天                 | commitment(story) |
| M5 | 昵称授权       | 用户明确允许昵称称呼               | commitment        |
| M6 | 第 100 次晚安  | 晚安类互动累计 100 次            | commitment(story) |
| M7 | 第一次故事闪回    | 联想链首次引用 story 记忆         | story             |

### 1.2 性格成长 —— 经历塑造型偏好 (受可塑性调节)

基线人格不变 (傲娇还是傲娇); 变化的是经历痕迹:



* **偏好演化**: 正向经历 (常陪、共同喜欢)→ like 微增；负向经历 (被忽视、被打断过多)→ dislike 微增。**步长 = 基础步长 × 记忆 salience × 可塑性 (阶段)**, 有上下限。婴儿期变化快、成熟期趋于稳定。

* **称呼演化**: 从 "主人" 到昵称 —— 需 M5 授权后才启用 (授权时刻是成长叙事的高光)。

* **语气微调**: 话痨度 / 粘人度随阶段 ±1 档 (不改变人格类型，只改变浓度)。

* **用户分轨**: 不同用户各有一份运行时偏好 (Loona 式 "谁喜欢摸头谁喜欢摸肚子"), 皮皮对主人 / 访客表现不同。

### 1.3 记忆成长 —— 记忆被编织成 "我们的故事"



* 关键记忆 (identity /commitment) 自动打 `story` 标签，沉淀为共同回忆。

* 成长引擎按时间线把共同回忆组织为：相遇 → 约定 → 变化 → 纪念。

* 联想链念头 (机制 1) 优先引用 story 记忆 —— 闪回带历史脉络 ("上次也是晚霞，那时候我们还不熟呢")。

### 1.4 表达成长 —— 会看人下菜、会学你说话 (见 §4)

## 2. 成长引擎 GrowthEngine (核心机制)

### 2.1 数据结构



```
@dataclass

class GrowthProfile:

&#x20;   user\_id: str

&#x20;   stage: int = 1                    # S1\~S4

&#x20;   stage\_since: float = 0.0          # 当前阶段进入时间

&#x20;   meet\_date: float = 0.0            # 相遇日(首次认主)

&#x20;   nickname\_authorized: bool = False

&#x20;   milestones: list\[str] = field(default\_factory=list)      # M1\~M7 编码

&#x20;   preferences: dict = field(default\_factory=dict)          # 运行时偏好快照 {"like":\[...], "dislike":\[...]}

&#x20;   learned\_expressions: dict = field(default\_factory=dict)  # {"文本": {"count": n, "last\_used": t}}

&#x20;   stats: dict = field(default\_factory=dict)                # {"active\_days": n, "turns": n, "night\_wells": n}
```

### 2.2 运行时序 (挂 `orchestrator._post_turn`, 异步、单向、不阻塞)



```
回合结束(\_post\_turn)

&#x20;  ├─ 1. update\_stats(): 活跃天数 / 轮次累计

&#x20;  ├─ 2. update\_stage():  检查推进/回落(硬性条件 + 冷却)

&#x20;  ├─ 3. check\_milestones(): M1\~M7 命中 → 写 growth\_milestones + commitment 记忆

&#x20;  ├─ 4. evolve\_preferences(): 按本轮情绪 × salience × 可塑性 微调 like/dislike

&#x20;  ├─ 5. learn\_expressions(): 主人文本高频表达拾取(≥3 次入库)

&#x20;  └─ 6. growth\_log 落盘: 所有演化事件留痕(可回看)
```

### 2.3 可塑性曲线 (本版核心新增机制)

**原则 (源自 Moxy 观察): 早期可塑性强、后期收敛稳定。** 这同时解决两个问题:①初期快速形成 "你的皮皮"(专属感);②后期人格不漂移 (一致性)。演化方程:



```
delta = base\_step × salience\_norm × plasticity(stage) × polarity

like\_new  = clamp(like + delta, 0, cap)

cap       = 基线 like 的 ±3 档(有界)

polarity  = +1 正向经历 / -1 负向经历
```



| 阶段   | S1 婴儿           | S2 幼儿 | S3 少年      | S4 成熟           |
| ---- | --------------- | ----- | ---------- | --------------- |
| 可塑性  | 1.00            | 0.60  | 0.35       | 0.15            |
| 行为含义 | 相处一周就明显变 "你的皮皮" | 变化放缓  | 只在高情绪事件时变化 | 基本稳定，仅里程碑级事件可撼动 |

### 2.4 设计原则 (0.1 保留 + 新增)



* **单向写入**: 只写不读，失败静默，绝不影响一轮回复。

* **全量可配置**: 每维度独立开关 (`growth.relationship.enabled` 等)。

* **有界演化**: 偏好有上限、阶段不可跳跃、可塑性自然收敛 —— 双重防漂移。

* **可回看**: 全部演化事件写入 `growth_log`,`/growth` 命令与面板可回看。

* **时间门槛**: 成长需要时间 (LOVOT slow-technology), 硬性天数不可省略。

## 4. 表达层设计

### 4.1 场景路由 (对话专家前置)



* **识别**(轻量规则词典，可扩展): 归一化后命中关键词


  * `anger` 被骂：闭嘴 / 滚 / 烦 / 傻 / 讨厌

  * `crisis` 危机：送走 / 不要你 / 换一个 / 讨厌我

  * `complain` 抱怨：又不听话 / 不吃 / 挑食 / 整天

  * `help` 求助：怎么办 / 建议 / 帮我

* 命中 → 从场景话术库按 **stage 解锁档** 选句 (可 LLM 润色); 未命中 → 回落现有 LLM 链路。

* 话术库 schema:`prompts/scenarios/<scene>.jinja`, 每句带 `stage_min`(最低解锁阶段)。

### 4.2 身体幽默话术库

persona prompt 注入身体设定 ("圆滚滚、有轮子、靠屏幕表情"); 被骂 → "我没有嘴，怎么闭呀？"(S3+)/ 被要求跑 → "轮子会累"(S3+)/ 被夸 → 得意转圈 (S2+)。陌生期只回客气话 —— 关系边界 (腾讯行业观点)。

### 4.3 高频表达拾取 (模仿学习)

回合后异步提取主人文本中的高频短句 / 口头禅 (count ≥3 入 `learned_expressions`), 在相关场景引用 —— "偷学主人说话" 的成精感 (二白学主人训狗的同款机制)。

### 4.4 解锁矩阵 (示意)



| 话术   | S1 | S2 | S3 | S4 |
| ---- | -- | -- | -- | -- |
| 客气回应 | ✅  | ✅  | ✅  | ✅  |
| 主动关心 | —  | ✅  | ✅  | ✅  |
| 身体玩笑 | —  | —  | ✅  | ✅  |
| 轻度毒舌 | —  | —  | ✅  | ✅  |
| 危机装傻 | —  | —  | —  | ✅  |

## 8. 验收标准 (自动化，test\_growth.py)



1. 阶段推进：第 1 天不可能 S4; 天数不足不推进；回落不低于 S2

2. 可塑性：同一正向事件，S1 的偏好变化量 > S4 的 (方程单调性断言)

3. 里程碑：M1\~M7 各自触发条件成立才写入；全部为 commitment/story 记忆，30 天后仍在

4. 表达解锁：同一输入在 S1 与 S4 走不同话术档 (场景路由断言)

5. 分轨：两个 user\_id 各有一份独立 GrowthProfile, 互不污染

6. 单向性：GrowthEngine 抛异常不影响 handle\_turn 结果 (故障注入测试)

## 10. 一句话总结

**成长 = 相处记录 (记忆)× 关系刻度 (阶段)× 演化规则 (可塑性曲线)× 表达输出 (解锁话术)**。

皮皮不是产品，是 "被你养出来的" —— 婴儿期变化快、成熟期长定型，任何克隆都拿不走这段历史。
