## 1. 设计目标与取舍原则

### 皮皮对硬件的真实需求

皮皮的瓶颈**不在算力，在音画采集质量与运动实时性**。

| 需求 | 硬件承担 | 算力要求 | 关键指标 |
|---|---|---|---|
| **听得清** | 麦克风阵列 + VAD | 低（16kHz 单通道） | 信噪比、远场拾音、回声抑制 |
| **看得见** | USB 摄像头 + 人脸检测 | 中（NPU/核显有帮助） | 低光表现、畸变、曝光稳定 |
| **动得了** | 轮趣 C30D（单板 MCU，micro-ROS） | 极低（MCU 足够） | 实时性、扭力、噪声 |
| **想得深** | 云端 LLM API | 无（网络即可） | — |

### 五条取舍原则

1. **主控双路线：x86（N100/N5015）与 ARM（RK3588）都可选。** x86 胜在**兼容性与生态**（USB 外设零驱动、ROS2 一键 apt 安装、OpenVINO 成熟）；ARM 胜在 **NPU 与能效**。下文 §3 有详细对比。
2. **主控只做"感知 + 决策"，运动控制全部下沉到一块板子。** **头部舵机、表情灯带、麦克纳姆轮电机全部交给轮趣 C30D**（STM32F407，板载 50Hz 舵机 PWM + WS2812 + 4 路编码器电机接口）。Linux 用户态绝不直接碰舵机与电机。
3. **移动指令的标准路径是 ROS2 话题。** 皮皮主程序发 `/cmd_vel`（Twist）与 `/pipi/head`（Float32MultiArray），micro-ROS agent 桥到 C30D。好处：以后加雷达 SLAM、遥控手柄、导航栈，只是在话题图里加节点。
4. **摄像头和麦克风只买「USB 免驱 UVC/UAC」。** CSI/MIPI 排线方案的驱动适配是无底洞。
5. **分档设计，不追求一步到位。** 先桌面版跑通全部软件，再上麦轮底盘。

> **为什么只用一块下位机（不挂 ESP32）？** C30D 本身就是一块 STM32F407 控制板，定时器通道足够同时输出多路 50Hz 舵机 PWM 与 WS2812 时序，并且自带 4 路电机编码器接口。把头部也交给它，省掉一条 UART 线、一颗需要单独烧固件的 MCU、以及两套固件版本对不齐的风险；实时性由同一颗 MCU 统一保证。

## 2. 系统拓扑总览

```
                    ┌──────────────────────────────────────────────┐
                    │  上位机主控（N100 / N5015 / RK3588，Linux+ROS2）│
                    │  ──────────────────────────────────────────  │
                    │  · 皮皮主程序（对话/情感/记忆/主动引擎）         │
                    │  · ASR / TTS / 视觉（人脸+表情+衣着）           │
                    │  · ROS2 节点 pipi_base                        │
                    │      pub /cmd_vel · pub /pipi/head · sub /odom │
                    │  · micro-ROS agent（serial 桥接）              │
                    └──┬───────┬───────┬────────────┬──────────────┘
                       │USB    │USB    │USB         │USB 921600
                       ▼       ▼       ▼            ▼
                ┌──────────┐┌───────┐┌───────┐ ┌────────────────────────┐
                │ 摄像头    ││麦克风 ││USB声卡│ │ 轮趣 C30D（单板下位机） │
                │UVC 1080P ││阵列6+1││+功放  │ │ STM32F407 + micro-ROS  │
                └──────────┘└───────┘└───┬───┘ │ ┌──────┬──────┬──────┐ │
                                         │     │ │50Hz  │WS2812│PWM+  │ │
                                         ▼     │ │PWM   │ 灯带 │编码器│ │
                                    ┌────────┐ │ └──┬───┴──┬───┴──┬───┘ │
                                    │ 喇叭    │ │    ▼      ▼      ▼     │
                                    │4Ω3W   │ │ 头部云台 表情灯  4×麦轮   │
                                    └────────┘ │ 2×MG996R       电机     │
                                               └────────────────────────┘

供电：主控 5V/4A Type-C（ARM）或 12V DC（x86 工控机）
      舵机 6V（独立，共地不共电）  |  底盘 12V 锂电（C30D 板载 5V/5A 可反哺 ARM 主控）
```

**三条解耦线**：
1. **USB 线**：感知与音频（摄像头/麦克风/声卡）——坏了自动降级到 mock。
2. **USB-micro-ROS 线**：**唯一的下位机链路**。C30D 一路串口同时跑 `/cmd_vel`（底盘）、`/pipi/head`（头部舵机+灯）与 `/odom`（里程计）。
3. **单板分工**：C30D 内部把舵机 PWM / 灯带时序 / 麦轮 PID 都做完，上位机只表达"想要的速度/角度"。

## 3. 主控选型（x86 与 ARM 两条线）

### 为什么引入 x86（N100 / N5015）

| 维度 | Intel N100 | Intel N5015 | RK3588（香橙派5Plus） |
|---|---|---|---|
| CPU | 4 核 Alder Lake-N，3.4GHz | 4 核 Jasper Lake，2.9GHz | 4×A76 + 4×A55 |
| AI 加速 | ❌ 无 NPU（核显 24EU + OpenVINO / AVX-VNNI） | ❌ 无 NPU（核显 16EU） | ✅ 6 TOPS NPU |
| **ROS2 安装** | **apt 一键，官方支持** | apt 一键 | 需手动装（arm64 坑多） |
| **USB 外设兼容性** | **完美（x86 驱动全）** | 完美 | 个别 UVC/声卡 quirks |
| 本地小 LLM（**3B Q4_K_M**） | **18~25 token/s** | 12~18 token/s | 8~12 token/s |
| 视觉推理（人脸检测） | CPU/OpenVINO 30fps+ | CPU 20fps+ | **NPU 50fps+** |
| 整机功耗 | 10~15W（无风扇工控机） | 8~12W | 8~15W |
| 存储 | NVMe SSD（快、稳） | NVMe/mSATA | TF 卡为主（慢、易坏） |
| 淘宝参考价 | **准系统 550~700 / 整机 750~1100** | **准系统 400~600 / 整机 600~800** | 8GB 板卡+散热+电源 700~900 |
| 体积形态 | 工控小盒子，直接放底盘上 | 同左 | 裸板需外壳 |

### 结论：主控推荐顺序

1. **⭐ N100 无风扇工控小主机（首推，尤其带麦轮底盘的完整形态）**
   - 皮皮要上 ROS2 + micro-ROS，x86 的 ROS2 是 `sudo apt install ros-humble-ros-base` 一键的事；ARM 板装 ROS2 要处理一堆 arm64 包兼容问题。
   - NVMe SSD 对 SQLite（皮皮的记忆数据库）和模型加载都是质的提升——TF 卡的随机读写是 SQLite 的噩梦。
   - 无风扇 = 零噪声（陪伴机器人贴着耳朵用，风扇声很出戏）。
   - x86 兼容性：USB 摄像头/声卡/串口插上就用，没有任何 ARM quirks。
   - **选购**：淘宝搜「N100 无风扇 迷你主机 准系统」，选 **550~700 元档（8G+256G）**。倍控/占美/盈驰等工控品牌都在这个区间。
2. **N5015（预算更紧时的 x86 平替）**
   - Jasper Lake 4 核，性能约 N100 的 60~70%，跑皮皮全部软件功能无压力（LLM 走云端，本地只做感知）。
   - N5015 多为工业渠道货；同代消费级 N5105/N5095 价格透明可做参照。**无风扇小主机 400~600 元**是合理区间（带 4 网口的工业板 ¥1200+ 家用不需要）。
3. **香橙派 5 Plus（RK3588，ARM 线首选）**
   - 如果确定**不走 ROS2 底盘**（只做桌面云台版），RK3588 的 NPU 视觉性价比仍然最高，¥700 拿下 8GB。
   - 劣势：ROS2 生态在 arm64 上折腾成本高；**要带麦轮底盘请直接上 x86**。
4. **入门验证：Radxa Rock 4D（RK3576，¥220~350）**
   - 纯软件验证最省的选择，视觉可跑（检测+识别），不做底盘。

> **关于本地跑 LLM**（数据已按 2026-10 社区实测更新）：
> N100 跑 **3B 量化模型（Q4_K_M）可达 18~25 token/s**，比我早期估的乐观。
> 中文正常语速约 4~6 字/秒，25 tok/s 意味着**生成速度比人说话快**——
> 所以本地推理的瓶颈**不是速度，是语言细腻度与人格稳定性**。
>
> **结论：不做本地部署，对话全部走云端。**
> 云端 Flash 档实测约 **¥0.15/千轮**（≈ 66 万轮/百元），成本根本不是约束；
> 本地跑 3B 会与视觉、ROS2 抢 N100 的 CPU，换来的只是"笨一点的闲聊"，
> 性价比不成立。降级链 = `qwen(主) → deepseek(备) → mock(规则回复)`，
> 两家云厂商物理隔离互为灾备，全挂才退本地规则话术。
>
> 完整选型（从小到大七档、价格实算、国内 7 家实测口径、避坑清单）
> 见 **[`LLM_SELECTION.md`](LLM_SELECTION.md)**。

## 4. 感知外设：视觉

| 型号方向 | 参数 | 价格 | 评价 |
|---|---|---|---|
| 1080P USB 工业模组（120° 无畸变版） | UVC 免驱、手动调焦 | **25~80 元** | ⭐ 性价比之王 |
| 1080P USB 无畸变宽动态（WDR） | UVC 免驱、WDR | **103~395 元** | 逆光救星 |
| IMX385 星光级 60fps | UVC 免驱、暗光优秀 | 约 390 元 | 夜间不补光也能认出人 |

**推荐：1080P UVC 免驱 + 120° + WDR，预算 80~130 元。**

- 皮皮只做**人脸检测/识别/表情/衣着颜色**，1080P 足够；`vision.fps: 1.5` 的超低采样率意味着 CPU 占用极低——**N100/N5015 没有 NPU 也完全跑得动**。
- **必须无畸变**：广角畸变会让 InsightFace 比对相似度下降，直接影响认主。
- **WDR 值得加钱**：逆光场景救回人脸轮廓。
- **坚决不碰 CSI 排线摄像头**（驱动无底洞）。

## 7. 运动系统：云台、C30D 单板与麦克纳姆轮底盘

### 7.1 头部云台（二轴）

| 零件 | 型号 | 价格 | 说明 |
|---|---|---|---|
| 云台支架 | 二自由度金属云台（含轴承） | **38 元** | 空心轴顺滑 |
| 舵机 ×2 | **MG996R** 金属齿轮 | **15~38 元/个** | 11kg·cm 扭力 |

对应 `Axis.HEAD_PAN` / `Axis.HEAD_TILT` / `Axis.LED`，**全部由 C30D 驱动**：
C30D 固件开两个 50Hz 定时器通道输出 PWM，皮皮只往 `/pipi/head`
发布 `[pan°, tilt°, led]` 三个数（见 `providers/motion/wheeltec.py`）。

### 7.2 下位机分工（单板全包）

| 下位机 | 职责 | 通信 | 价格 |
|---|---|---|---|
| **轮趣 C30D** | **头部云台舵机 + WS2812 灯带 + 麦轮底盘**：4 路编码器电机 PID、麦轮运动学解算、里程计、急停看门狗 | **micro-ROS（串口 921600）** | **约 500~650 元** |
| ~~ESP32-S3~~ | ~~头部云台 + 灯带~~ | — | **已移除**（C30D 定时器通道足够，省一条 UART + 一套固件） |

**轮趣 C30D 关键参数**：
- STM32F407VET6（Cortex-M4 168MHz），驱控一体：直接驱动 4 路编码器电机
- **多路舵机接口 + WS2812 数据口**，50Hz PWM 输出由固件定时器产生
- 支持**麦克纳姆轮 / 全向轮 / 差速**多种底盘构型（固件可配）
- 12V 锂电输入，**板载 5V/5A 输出可以给 ARM 主控供电**（移动形态省一路电源）
- 串口 + CAN 双通信；官方生态是 ROS/ROS2 下位机
- 淘宝轮趣（WHEELTEC）官方旗舰店有售

> **C30D 必须烧 micro-ROS 固件**（在官方固件基础上加一个 micro-ROS app），之后它在 ROS2 话题图里就是一个标准节点：
> 订阅 `/cmd_vel`（Twist）与 `/pipi/head`（Float32MultiArray），发布 `/odom`（Odometry）。
> **不要**用它的串口私有协议直连皮皮——那是上一代玩法，协议随固件版本漂移。
>
> **舵机与灯带都挂 C30D 的前提**：固件里要额外注册两个 50Hz PWM 通道（头部）和一个 WS2812 通道（灯带），
> 并让 micro-ROS 订阅回调同时更新这三路输出。参考实现骨架见 §8.3。

### 7.3 麦克纳姆轮底盘（皮皮的新自由度）

**为什么麦轮**：普通差速底盘只有前进+旋转两个自由度，而麦轮由 45° 辊子合成任意方向速度，支持**横移（strafe）**。皮皮因此获得一个独占动作：

```python
Axis.BASE_STRAFE        # 底盘横移 —— 麦轮专属
Gesture.SIDE_STEP       # 侧身滑开（傲娇/吃醋时平移拉开距离，极其传神）
```

运动学（4 轮速度合成，**C30D 固件已实现**，皮皮只发 vx/vy/wz）：
```
vx = (v1+v2+v3+v4)/4        # 前后
vy = (−v1+v2+v3−v4)/4       # 横移（麦轮独有）
wz = (−v1−v2+v3+v4)/(4·L)   # 自转
```

| 零件 | 选型 | 价格 |
|---|---|---|
| 麦克纳姆轮 ×4 | 60mm PP 麦轮（入门）/ 80mm PU 麦轮（进阶） | **80~150 元 / 200~400 元** |
| 编码器电机 ×4 | MG513P30 / GB37-520 霍尔编码器电机（轮趣配套） | **35~60 元/个** |
| 底盘铝板/亚克力 | 双层底板（含电机支架孔位） | 40~80 元 |
| 电池 | 12V（3S）锂电 5000mAh + 充电器 | 100~150 元 |

**麦轮注意事项**：
- 滚动阻力大，**电机扭力要留余量**（扭力不够会空转打滑、转向精度崩）。
- 对地面有要求：硬地最佳，长毛地毯会卡辊子。
- 不追求高速——麦轮的强项是**低速全向灵动**，正好匹配陪伴机器人。

## 8. ROS2 + micro-ROS 部署链路

### 数据流

```
皮皮主程序（pipi_base 节点）
    │  publish geometry_msgs/Twist            → /cmd_vel      （底盘：速度）
    │  publish std_msgs/Float32MultiArray     → /pipi/head    （头部：角度+灯）
    ▼
ROS2（Humble/Jazzy，跑在主控上）
    │  DDS 发现与路由
    ▼
micro-ROS agent（主控上的一个进程，串口桥）
    $ ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 921600
    ▼
轮趣 C30D（micro-ROS 固件，STM32 内跑 micro-ROS 客户端）
    │  订阅 /cmd_vel   → 麦轮解算 → 4 路 PID  → 电机
    │  订阅 /pipi/head → 50Hz 舵机 PWM ×2 + WS2812 灯带
    │  发布 /odom（编码器里程计回传）
    ▼
4× 编码器电机 + 4× 麦克纳姆轮 + 头部云台（2×MG996R）+ 表情灯带
```

### 8.2 头部话题数组布局（固件必须对齐）

`/pipi/head` 是 `std_msgs/Float32MultiArray`，`data` 三个浮点数按固定顺序：

| 下标 | 名称 | 单位 / 范围 | 说明 |
|---|---|---|---|
| `data[0]` | `head_pan` | 度，−120 .. +120 | 左右舵机绝对角度，**不是速度** |
| `data[1]` | `head_tilt` | 度，−45 .. +45 | 俯仰舵机绝对角度 |
| `data[2]` | `led` | 0.0 .. 1.0 | 表情灯亮度 |

上位机侧（`providers/motion/wheeltec.py` 的 `HEAD_JOINTS`）与固件侧必须一致；
改动布局要同时改这两处，否则云台会朝错误方向运动。

**语义差异（重要）**：
- 头部是**位置语义**——发了角度就停在角度，不需要周期性重发，**不设软件看门狗**。
- 底盘是**速度语义**——发了速度就会一直走，因此 `WheeltecC30D` 在 500ms 无新指令后自动补发全零 Twist。
- `emergency_stop()` **只把底盘归零 + 灯灭**，不动云台角度——突然垂头可能砸到人。

### 8.3 C30D 固件要点（自写 micro-ROS app）

C30D 官方固件本身不带 ROS2 话题，需要在外设初始化后挂一个 micro-ROS app。
要点（骨架示意图，实际以 STM32CubeMX + micro_ros_client 为准）：

```c
/* 1) 外设：4 路编码器正交解码 + 4 路电机 PWM + 2 路 50Hz 舵机 PWM + WS2812 DMA */
MX_TIM1_Init();   /* 电机 PWM */
MX_TIM2_Init();   /* 舵机 PWM，PSC/ARR 配到 50Hz（20ms 周期） */
MX_TIM4_Init();   /* 编码器模式 */
ws2812_init();    /* DMA + TIM，或 SPI 移位法 */

/* 2) micro-ROS 会话 + 三次实体 */
rcl_allocator_t allocator = rcl_get_default_allocator();
rclc_support_t  support;   rclc_support_init(&support, 0, NULL, &allocator);
rcl_node_t      node;      rclc_node_init_default(&node, "c30d", "", &support);

/* 订阅 1：底盘速度（geometry_msgs/Twist） */
rcl_subscription_t sub_cmd;
geometry_msgs__msg__Twist cmd_msg;
rclc_subscription_init_default(&sub_cmd, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(geometry_msgs, msg, Twist), "/cmd_vel");

/* 订阅 2：头部三路（std_msgs/Float32MultiArray） */
rcl_subscription_t sub_head;
std_msgs__msg__Float32MultiArray head_msg;
float head_buf[3];                       /* 与 HEAD_JOINTS 顺序一致 */
head_msg.data.data = head_buf; head_msg.data.size = 3; head_msg.data.capacity = 3;
rclc_subscription_init_default(&sub_head, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Float32MultiArray), "/pipi/head");

/* 发布：里程计（nav_msgs/Odometry） */
rcl_publisher_t pub_odom;
nav_msgs__msg__Odometry odom_msg;
rclc_publisher_init_default(&pub_odom, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(nav_msgs, msg, Odometry), "/odom");

/* 3) executor + 回调 */
void on_cmd(const void *msgin) {
  const geometry_msgs__msg__Twist *t = msgin;
  mcnemum_solve(t->linear.x, t->linear.y, t->angular.z);   /* 麦轮解算 → 4 路目标速度 */
  last_cmd_tick = HAL_GetTick();                            /* 喂看门狗 */
}
void on_head(const void *msgin) {
  const std_msgs__msg__Float32MultiArray *h = msgin;
  if (h->data.size < 3) return;
  servo_set_deg(SERVO_PAN,  h->data.data[0]);
  servo_set_deg(SERVO_TILT, h->data.data[1]);
  ws2812_set_brightness(h->data.data[2]);
}

/* 4) 500ms 看门狗：话题长时间不来 → 底盘速度归零（舵机保持角度） */
if (HAL_GetTick() - last_cmd_tick > 500) mcnemum_solve(0, 0, 0);
```

**⚠️ 舵机/Servo 频率提醒**：MG996R 是模拟舵机，PWM 必须是稳定 50Hz（脉宽 0.5~2.5ms 对应 −90°..+90°）。
`HEAD_PAN_DEG`/`HEAD_TILT_DEG` 定义的行程要**小于等于机械极限**，上位机满档（±1.0）即映射到此行程。

- **急停**：`emergency_stop()` 发全零 Twist + 关灯，并保持云台角度。

## 9. 供电、散热与结构

### 供电

| 负载 | 电压 | 供电方式 |
|---|---|---|
| x86 主控（N100/N5015） | 12V DC | 桌面版：原装适配器；**移动版：3S 电池直供 + DC 稳压**（C30D 的 5V/5A 带不动 x86） |
| ARM 主控（RK3588） | 5V/4A Type-C | **移动版可由 C30D 板载 5V/5A 反哺**（ARM 的小优势） |
| 摄像头 + 麦阵 | 5V | 主控 USB 口 |
| 舵机 ×2（MG996R） | 6V | 独立 6V 5A（或电池+BEC），**只共地不共正极**；信号线接 C30D 舵机口 |
| C30D + 4 电机 | 12V | 3S 锂电直供（C30D 原生输入） |
| 功放 + 喇叭 | 5V | 独立 USB |

**铁律**：① 主控电源足额（ARM 5V/4A；x86 按原装适配器）；② 舵机/电机与主控**分电源、只共地**；③ 舵机电源并联 1000µF 电容；④ 星型接地。

### 散热

- **N100/N5015 无风扇工控机**：铝合金机身被动散热，出厂即解决——零噪声，这也是选它们的原因之一。
- **RK3588**：必须散热片+风扇，否则 NPU 降频。

### 结构

- **桌面版**：3D 打印头部外壳（摄像头+灯带+麦阵三孔位），约 30 元耗材。
- **移动版**：**真·十字形底盘**（4 轮 90° 均布，圆柱壳体）——
  完整设计见 **[`CHASSIS.md`](CHASSIS.md)**，参数化模型见 **[`hardware/chassis.scad`](../hardware/chassis.scad)**。

| 关键尺寸 | 值 |
|---|---|
| 轮距 / 轴距 | **240 × 240 mm**（十字对称） |
| 车体外接圆 | **Ø300 mm**（小于它盖不住头部） |
| 中心枢纽半径 | 62 mm（内容 C30D + 电池包） |
| 底板 | 4mm 6061 铝（推荐）/ PETG 板 |
| **整机重量** | **3.29 kg** |
| **重心离地** | **55.2 mm**（电池下挂压低 19%） |
| 侧翻裕度 | **21.4×** |

**三层堆叠（自下而上）**：麦轮底盘（电池**下挂**在底板正下方）→ C30D 电控层 → 主控 N100 → 云台与头部。
**重心放低**（电池在最底层）+ 轮距 240mm，麦轮小车急停不翻。

> **为什么是十字而不是方形**：皮皮是圆柱壳（陪伴机器人形态），四轮 90° 均布天然贴合圆柱、旋转时车体扫过就是自身轮廓，不会像方形底盘那样「甩角」蹭家具。代价是绕 Z 力矩臂小 29.3%，靠把 footprint 从 170mm 放大到 240mm 补回来。详见 `CHASSIS.md` §1。

### 自动回充（归桩充电）

**麦轮底盘在回充上有一个别人没有的优势。** 回充的难点是同时把「距离」和「偏角」归零——差速底盘只有 `(vx, wz)`，两者耦合，只能倒 S 形曲线或反复修正。麦轮有 `(vx, vy, wz)` **三个正交自由度**，可以把对接解耦成三段独立闭环：

| 段 | 控制量 | 做什么 |
|---|---|---|
| ① 缩距 | `Twist.linear.x` | 沿桩法线靠近 |
| ② 调心偏 | `Twist.linear.y` | 纯横向平移 |
| ③ 调角偏 | `Twist.angular.z` | 原地旋转 |

**三段互不干扰 → 三个单变量 P 控制器就够，C30D 固件一行都不用改**（这三路本来就是 `/cmd_vel` 自带字段）。

**引导方式**：远程 `AprilTag 视觉`（复用已有 1080P 摄像头，桩面贴纸 ¥1）+ 近程 `双红外对管`（桩上 2 发、车尾 2 收，¥30 内）。不需要激光雷达、不需要加算力。

| 关键参数 | 值 |
|---|---|
| 触发 | 电量 ≤25% / 闲置 ≥20min / 到点 23:30 |
| 远程→近程切换 | 0.35 m |
| 对接限速 | `vx` 0.15 / `vy` 0.06 / `wz` 0.35（**回充专用限幅**） |
| 桩体 | 260 × 120 × 48 mm，中央开口 210 mm |
| 充电 | **12.6V / 3.5A（0.5C）≈ 44W** |
| 触点 | **竖直弹片**（不积灰、麦轮压不到、顶入自清洁） |
| 桩成本 | **≈ ¥80~150** |

> **为什么不用无线充电？** 结论是**可以但不必**。皮皮充电 44W，无线（感应式 70~80%）要把 **11~19W 变成热**，而底盘是密闭的；触点方案损耗只有 **2.3W**（3.5A × 20mΩ 接触电阻，毫瓦级发热）。更反直觉的是**无线对"对得准"的要求更高**——Ø40 线圈偏移超 13mm 效率就断崖，而弹片容差 ±15mm 以上。无线真正划算的场景是 **24h 高稼动 / 多台机器人 / 潮湿粉尘 / 需完全密封**，皮皮（家庭、单台、每晚充一次、地面干净）一个都不占。
>
> **留了后路**：触点座与无线接收线圈占**同一块底板区域**，将来想切无线，换底板 + 去掉弹片即可，**车体结构和 `DockController` 一行都不用改**。完整效率/发热/对齐/成本对比见 `CHASSIS.md` §12.6。

**代码落地**（全部走已有架构，无新话题、无新固件、无新进程）：

| 文件 | 改动 |
|---|---|
| `src/pipi/orchestration/dock.py` | **新建** `DockController`（状态机 + 三段式 P 控制，纯逻辑可单测） |

## 11. 与现有代码的对接

### 11.1 目录结构

```
src/pipi/hardware/
├── base.py        # CameraDriver / MicDriver / SpeakerDriver / MCUBridge 协议
├── sim/           # 全模拟实现（当前默认）
└── rockchip/      # 板卡真实驱动（预留；x86 驱动同样在这一层落地）
```

x86 主控的驱动与 rockchip 目录**同级**落地即可——驱动只依赖 USB/ALSA，与 SoC 无关，多数类可直接复用。

### 11.2 MotionProvider 全景

| provider | 覆盖轴 | 通信 | 依赖 |
|---|---|---|---|
| `mock` | 全部（日志） | — | 无 |
| `wheeltec` | **HEAD_PAN / HEAD_TILT / LED + BASE_FORWARD / BASE_STRAFE / BASE_ROTATE**（全机六轴） | **ROS2：`/cmd_vel` + `/pipi/head` + `/odom`（micro-ROS）** | rclpy + agent |

切换只改一行配置（`motion.provider: mock | wheeltec`），业务代码零改动。
单板方案不再需要轴级路由（`composite` 已随 ESP32 一起移除）。

### 11.3 三个必踩的实现坑（已写进代码注释）

1. **阻塞 IO 必须 `asyncio.to_thread()` 包装**（OpenCV `cap.read()`、ROS2 publish），否则事件循环卡死、主动引擎失效。
2. **`is_available()` 必须真检测**（`/dev/video0` 存在、`rclpy` 可导入），不能返回 True——降级链靠它判断。
3. **WS2812 / 舵机 PWM / 电机 PID 一律交给 C30D**，Linux 用户态绝不直接驱动。

### 11.4 Axis → 物理映射

| Axis | 执行器 | 经由 | 语义 |
|---|---|---|---|
| `HEAD_PAN` | MG996R #1 | C30D 50Hz PWM | **角度**（−1..1 → ±120°） |
| `HEAD_TILT` | MG996R #2 | C30D 50Hz PWM | **角度**（−1..1 → ±45°） |
| `BASE_FORWARD` | 麦轮底盘 | **ROS2 Twist.linear.x** | 速度档（−1..1 → ±0.5 m/s） |
| `BASE_STRAFE` | 麦轮底盘 | **ROS2 Twist.linear.y** | 速度档（−1..1 → ±0.4 m/s） |
| `BASE_ROTATE` | 麦轮底盘 | **ROS2 Twist.angular.z** | 速度档（−1..1 → ±1.5 rad/s） |
| `LED` | WS2812 | C30D 数据口 | 亮度 0..1 |
| `SPEAKER_VOLUME` | 主控软件混音 | — | 不经 MCU |

**两套语义必须分清**：底盘三轴是**速度语义**（不复位会一直开走），`WheeltecC30D` 内置 500ms 看门狗自动归零；
头部两轴与 LED 是**位置语义**（发了就停住），不需要看门狗，急停时也刻意保留角度。

|---|---|---|
| ARM 板用手机快充头 | 满载掉压 → 重启/NPU 降频 | **5V/4A** 专用电源 |
| 舵机和主控共用电源 | 舵机堵转 → **主板重启** | 独立 6V，只共地不共正极 |
| x86 主机接 C30D 的 5V/5A | **点不亮**（x86 要 12V） | x86 用 3S 电池直供 + DC 稳压；5V/5A 只给 ARM |
| 电源无滤波电容 | 电机噪声串音频 → 爆音 | 1000µF 电解电容并联 |

### 🔴 选型类

| 坑 | 后果 | 规避 |
|---|---|---|
| ARM 板折腾 ROS2 | arm64 包兼容坑多 | **带底盘就上 x86（N100/N5015）** |
| C30D 用串口私有协议直连 | 固件升级协议漂移 | **烧 micro-ROS 固件，走 ROS2 话题** |
| C30D 固件没加头部话题 | 舵机不动（只有底盘响应） | 固件里注册 `/pipi/head` 订阅（§8.3） |
| 头部话题数组顺序写反 | 云台朝错误方向转 | 固件 `data[0..2]` 与 `HEAD_JOINTS` 严格对齐 |
| CSI/MIPI 排线摄像头 | 驱动调不通 | 只买 **USB UVC 免驱** |
| 广角畸变镜头（>150°） | 人脸比对下降，认主不准 | 120° 且标明"无畸变" |
| MG90S 带重摄像头 | 堵转抖动 | 负载 >300g 必须 **MG996R** |
| 麦轮配弱电机 | 空转打滑、转向崩 | 编码器电机**扭力留余量**（MG513P30 级） |
| 麦轮买成 4 个同向（4L 或 4R） | **不能横移**，直行跑偏 | 跟客服确认是 **2L + 2R**（`CHASSIS.md` §4） |
| 按轮毂宽 31mm 算相邻轮间距 | 斜对角**辊子互啃**、电机堵转 | 按 **49mm**（含辊子外凸）算 → 间距 ≥69mm |
| 底盘用 3D 打印件（PETG 板） | 急停时底板扭转 → 四轮不共面 | **底板切 4mm 6061 铝**（`CHASSIS.md` §10） |
| 电池装在底板上方 | 重心抬高 13mm，急停易翘轮 | **电池下挂**（`CHASSIS.md` §6） |
| 底盘电池用 4S/2S | 4S 超压烧 C30D；2S 转速不够 | **只上 3S**（11.1V 标称 / 12.6V 满） |
| 电池无 BMS 或 BMS 电流不足 | 过放/过流 → 鼓包起火 | **3S 均衡 BMS，≥20A** |

### 🟡 实现类

| 坑 | 后果 | 规避 |
|---|---|---|
| 协程里直接 `cap.read()` / publish | 事件循环卡死 | `asyncio.to_thread()` |
| Linux GPIO 驱 WS2812 | 时序抖动闪灯 | 走 C30D 的 WS2812 数据口 |
| 底盘速度指令不看门狗 | 主控崩了小车开走 | 软件 500ms + 固件看门狗双保险 |
| 急停把云台也归零 | 头部瞬间垂下、可能砸到人 | 急停只停底盘 + 关灯，保留云台角度 |
| micro-ROS agent 没常驻 | 重启后底盘/舵机全失联 | systemd 服务化 |
| 底盘线缆不过孔固定 | 急转时线被卷入麦轮辊子 | 过孔 + **热熔胶点固**（`CHASSIS.md` §7） |

### 🟡 采购类

- N100/N5015 工控机认准**无风扇**（有风扇的版本噪声大且进灰）；问清是否含电源。
- C30D 在**轮趣官方旗舰店**买，备注要 **micro-ROS 固件**（部分批次默认 ROS1 固件）。
- 麦轮散件常缺货，**轮+电机+底盘尽量同店买套装**，孔位才匹配。
- 摄像头让客服提供 **TV Distortion 数值**（<2% 为佳）和**实际帧率**。
